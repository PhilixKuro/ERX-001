## 系统现状

### 项目定位

基于 ERPNext 的二次开发项目。上游 ERPNext 与 Frappe 框架以自有 fork 的 submodule 形态引入，本项目的功能以 Frappe app 形态叠加在其上。

### 技术栈

| 层 | 技术 |
|---|---|
| 框架 | Frappe Framework `version-16`（16.34.0） |
| 业务基座 | ERPNext `version-16`（16.35.0） |
| 后端 | Python 3.14 |
| 前端 | Frappe Desk（DocType 驱动），Node 24 |
| 数据库 | MariaDB 11.8 |
| 缓存 / 队列 | Redis（cache 与 queue 各一实例） |

### 模块结构与职责

| 路径 | 职责 | 形态 |
|---|---|---|
| `apps/frappe/` | Frappe 框架，ERPNext 的依赖 | fork 的 submodule，锁 `version-16` |
| `apps/erpnext/` | ERP 业务基座 | fork 的 submodule，锁 `version-16` |
| 自有 app | 本项目全部二次开发内容 | 待创建 |
| `docker/` | 容器化开发环境与迁移脚本 | 本仓库自有 |
| `frappe-bench/` | bench 本体（venv、站点、构建产物） | 由 `docker/up.sh` 生成，不进 git |
| `docs/流程体系/` | 跨项目共享的流程规范（SPS） | submodule |

frappe 与 erpnext 版本须配套，同为 `version-16`。扩展方式与上游同步流程见 `开发守则.md`。

### 开发环境

容器化，宿主机只需 Docker。用法见 [../docker/README.md](../docker/README.md)。

- 站点 `erx.localhost`，web 端口 8000，登录 `Administrator` / `admin`
- 界面语言中文，公司 `ERX Demo`（演示数据在 `ERX Demo (Demo)` 名下）
- bench 的 `apps/` 是指向本仓库 submodule 的符号链接，**改源码即时生效**
- 数据库与 Redis 用 named volume；换机器靠 `backup.sh` / `restore.sh` 迁移数据，`up.sh` 重建环境

### 已知限制 / 技术债

- **符号链接方案需三处路径修补**：`apps/` 用符号链接换取「改源码即时生效」，代价是 socketio 的 bench 根推导、`bench build` 产物落点、erpnext `banking` 子应用的相对路径三处会失准。修法已固化在 `docker/scripts/setup.sh` 并注明原因（详见 `docker/README.md`）。
- 对 `apps/erpnext/` 或 `apps/frappe/` 的源码改动须登记于此（见 `开发守则.md`）。
