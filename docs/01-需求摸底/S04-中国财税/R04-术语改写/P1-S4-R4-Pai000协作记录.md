**⑤ 新旧词对照表的留痕方式裁决**

**提出者：** Claude（给两档）／用户（裁决）

**背景：** 改写必然产生一份新旧词对照表。它落在哪里有矛盾：落进产物最便于查阅，但那份产物此后每轮都会被当依据载入，**对照表自身就成了新的触发源**——等于把本轮的成果抵消掉。

**选项：**

| 选项 | 描述 | 优点 | 缺点 |
|---|---|---|---|
| **不入库，只靠 git** | 产物一律用代号，字面对照取 tag 前后版本 diff | 留痕完整（git 全量保存）而工作树不留新触发源 | 查对照要跑一次 git 命令 |
| 写进协作记录 | 对照表完整落在本文件 | 查阅最方便 | 本文件成为新的触发源，且它会被此后各轮当依据载入 |

**用户回答：** **不入库，只靠 git。**

**结论：** **五类词的字面对照不写进任何产物**，本协作记录与回执一律用甲乙丙丁戊代号。字面比对方式：`git diff P1-S4-R4-start -- <文件>`。本裁决也是本文件头部「代号约定」那张表的来处。

### 取证段（本步实际跑过的清点）

**手段**：`grep -rc` 逐词逐文件计数，范围 `docs/`／`Spike/`／`docker/`／根目录 `*.md`，排除 `frappe-bench/`（不进版本管理）。五类词各自独立计数，避免一个词的高频掩盖另一个词的分布。

**可复现路径**（讨论契约 §2 纪律 9）：

```bash
# 逐文件五类计数（词面本身按裁决三不落库，下式中的 <甲>…<戊> 取 tag 前版本里的实际词面）
for f in $(grep -rl -iE "<甲>|<乙>|<丙>|<戊>|<丁>" --include="*.md" docs/ Spike/ docker/ *.md); do
  printf "%s 甲=%s 乙=%s 丙=%s 戊=%s 丁=%s\n" "$f" \
    "$(grep -ci '<甲>' "$f")" "$(grep -c '<乙>' "$f")" \
    "$(grep -cE '<丙>' "$f")" "$(grep -cE '<戊>' "$f")" "$(grep -ciE '<丁>' "$f")"
done
```

**两项核实结果**（写在此处因它们是事实、非讨论结论）：

1. **git 工作树在本轮开工前是干净的**（`git status --short` 仅一个未跟踪的 `grep.exe.stackdump`），SPS submodule 亦干净 ⇒ 本轮的全部改动可由 `git diff` 单独辨出。
2. **已有 tag**：`P1-S4-R1-start`、`P1-S4-R3-start`（均本地未推）⇒ `P1-S4-R4-start` 的命名与既有序列一致。
