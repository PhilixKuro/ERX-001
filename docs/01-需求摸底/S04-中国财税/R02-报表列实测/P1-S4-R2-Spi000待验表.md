## 两条判定对 `SH-P1S4002` 的答复（只陈事实，去向由 B 步与用户定）

> 交接纪律 5「不在表里写建议」——本节**不判断自写还是配模板**，只把登记册那句「若任一条实测后不成立，自写这个决定就该重判」对应到实测结果上。

`SH-P1S4002` 登记的两条判据，**实测后一条成立、一条不成立**：

| 判据 | R1 原文 | 实测 |
|---|---|---|
| ① 双栏＋两会计年度时列头的实际长相 | 隐含「列头是年份」 | **缺口成立，但判据描述不准**：实际是 `段标签 - 期间标签`，段标签那一半**由模板控制**。逐字合规仍做不到 |
| ② `accumulated_values` 是否真无法一列累计一列单月 | 「引擎架构上做不到」 | **不成立**。两列可并存，`balance_type` 是行级字段 |

**故登记册那句触发条件已命中**（「任一条实测后不成立」）。**⇒ `SH-P1S4002` 可标为已做，但它引出的重判是 B 步的事**，本 Round 不做该判断（`play-spike` 纪律：不判断「那这件事该怎么结论」）。

**一并交出三件 B 步重判时要用的事实**，免得它按「两列能做」就直接倒向配模板：

1. **② 成立有前提**——`Closing Balance` 须靠年结 PCV 才等于本年累计，而那块本 Stage 自己还没做；
2. **① 仍然成立**——列头逐字合规在模板层无解，这一条没被推翻；
3. **列数**——`Monthly` 下 26 列、`Yearly` 下每段 1 列，都不是法定三列形态。

（按规范 §2.2 三点，`Spi000` 优先交代的三类）

1. **最该先看的：V-26 的 `no-go` 直接推翻 R1「BS＋PL 自写」的一半判据，代价最大。** 若这条判错，B 步会照一个错事实重判方案形态。**查法**：读 `Spike/V26-out/accumulated-vs-monthly.json` 的 `DECISIVE` 键（四个布尔 ＋ 两组按月数值），对照同文件 `raw_gl_pl_movement_by_month`（`{"2026-09": -719.5}`）确认引擎数与裸 GL 一致；再读 `Spike/V26-out/seg2-crossperiod.json` 的 `DECISIVE_seg2`（**Oct 区间内零笔账却报 1045.0**）与 `get_opening_balances_source`（那条 `1900-01-01` 回退路径）。要重跑改 `watch` 月份列表即可。
2. **判定是「当前现状」还是「设计意图」**：**两条都实跑了真引擎**（`FinancialReportEngine().execute()`），不是只读代码。V-25 的机制解释（`:1727-1728`）与 V-26 的 `continue` 分支是读码，但**结论本身来自实跑输出**。唯一纯读码的是 `Custom API` 那条契约——我读了 `:1185` 的调用签名，**没有真写一个 Custom API 方法跑一遍**。若 B 步要拿「Custom API 管不了列」当判据，值得补一次实跑。
3. **观察范围的边界**：`erx.localhost` 单站点／单公司／**单会计年度**／损益 GL 仅 3 条且全在同一天。**三件未验**：① **年结 PCV 能否把损益科目结平、让累计列从本年起算**（代码路径在 `:536-547`，但建 PCV 是真写入，本探针不碰）；② 多月有账时逐月累计值是否正确递增（站点只有一个月有账，验不了）；③ 自建模板给 `Column Break` 填**中文** `display_name` 后列头长什么样（按 `:1727` 应是 `中文 - 2025`，V-26 里已顺带见到中文段标签生效，但**没在双栏 BS ＋ 两会计年度那个组合上单独验过**）。**第 ① 条是「配模板」这条路的最后一块拼图。**
4. **拿不准处（两条）**：
   - **`Closing Balance` ↔「本年累计」这个映射是我选的**，上游没有任何字段叫「本年累计」。seg2 已把代价查清（滚动余额、依赖年结），但**是否接受这个代价是判断题**，属 B 步与用户。

## ⚠ 一处必须声明的探针自身产物，不是产品缺陷

V-25 的纯函数段我用 `ignore_fiscal_year=True` 调 `get_period_list`，`accumulated_values=True` 时标签跑出 **`-2025`／`-Jan 25`**（前导横线）。成因是该参数跳过 `from_date_fiscal_year_start_date` 赋值，`formatdate(None)` 得空串，于是 `"" + "-" + "2025"`。

**真实报表路径不走这条**：`_initialize_context():279-288` 调 `get_period_list` 时**根本没传 `accumulated_values`**（取默认 `False`），实测输出是干净的 `2025`／`2026`。**这条横线是探针造的，不要当产品 bug。** 附带得一条真事实：**FRT 路径下 `get_period_list` 的累计标签分支是死代码。**
