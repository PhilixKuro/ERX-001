## 演化过程

#### 第 1 步：两个默认科目选哪个；「上月未结」判到什么程度

**① 库存调整科目 `stock_adjustment_account`**
**提出者：** Claude
**背景：** FD-004：现值 `400103 生产成本-库存调整`（成本类，`root_type = Asset`），盘盈盘亏挂在存货里，永远进不了利润表。用户在 R14 裁决里把选科目授权给 Claude，按 DEC-119「满足规范为前提、会计习惯为首要」定。查证的事实：
- 上游一张单据只用这**一个**科目收差额，盘盈记贷方、盘亏记借方（`stock_reconciliation.py:70`、`stock_entry.py:2742`、`accounts/utils.py:1910-1921`）。另外三处也用它兜底：无费用科目的物料入库（`stock_entry_utils.py:134`）、委外收货的分摊损失（`subcontracting_receipt.py:944`）、BOM／Stock Entry Type 带出的默认费用科目。
- 上游界面过滤要求 `root_type = Expense` 且 `account_type = Stock Adjustment`（`company.js:332`）；服务端 `validate_default_accounts` 只查是否属本公司、是否组科目、是否停用（`company.py:248-290`）。**本表 266 个科目里没有一个两条都满足**，选哪个都得登记偏离。
- 小企业会计准则附录 1901：盘盈、盘亏先记「待处理财产损溢」，报经批准后，盘亏扣掉残料与赔偿后的差额转营业外支出，盘盈转营业外收入；「年末结账前处理完毕，处理后本科目应无余额」（[财政部原文](https://kjs.mof.gov.cn/zhengcefabu/201111/P020111118325852734144.pdf)、[1901 科目全文](https://www.zkemu.com/acc1/zcl/1901/)）。
- 本表 1901 的科目名是「待处理财产损溢_非流动资产」，只有这一个，没有流动资产那一个明细（科目表按 zelin 原字节入库，IT-035，不能加科目）。

**选项：**

| 选项 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| A `1901 待处理财产损溢` | 盘点差额先挂 1901；会计按批准结果用 Journal Entry 转入营业外收支；12 月结转状态检查 1901 有余额就提示 | 唯一能**完全**照准则走的选法：残料、赔偿、批准都要人来判断，系统本来也替不了；也是国内会计的通行做法；第一次做期初库存盘点时不会撞上「差额科目不能是损益类」的上游校验（`stock_reconciliation.py:981-990`） | 不是一步进利润表，要会计手工转；1901 在资产负债表第 28 行「其他非流动资产」，年中挂着的存货差额会显示在非流动资产里；科目名写着「非流动资产」；Company 表单上重选这个字段时下拉里看不到 1901 |
| B `5301050 盘盈利得` | 差额直接进营业外收入 | 一步进利润表；盘盈的去向与准则一致 | 盘亏会变成营业外收入的负数，准则要求的是营业外支出；跳过了准则的批准环节，残料与赔偿也没地方体现 |
| C `5602080 管理费用_财产损耗、盘亏及毁损损失` | 差额直接进管理费用 | 一步进利润表；科目名正好是「盘亏」 | 小企业准则要求的是营业外收支，不是管理费用；盘盈会变成管理费用的负数 |

**用户回答：** 用户在 R14 F 审核裁决里授权按会计习惯由 Claude 定（「继续沿用」DEC-121 的授权），本轮没有另外指示。
**结论：** 取 **A**（DEC-122）。B、C 是让一个科目同时收两个方向，必然有一个方向记反；A 是唯一能让两个方向都按准则落账的选法，代价是需要会计手工转一笔，而这一笔本来就要人来判断。为了不让「进不了利润表」又变成静默的：12 月结转状态检查 1901，有余额就出提示，资产负债表说明行显示出来。上游界面过滤这一处偏离登记进方案总纲偏离表与 README。

**② 资产处置损益科目 `disposal_account`**
**提出者：** Claude
**背景：** 现值 `1606 固定资产清理`（资产类），上游界面过滤要求损益类（`company.js:307`）。查证：上游处置时贷记固定资产原价、借记累计折旧，再把**净损益这一笔**记到 `disposal_account`，收益记贷方、损失记借方（`depreciation.py:635-680、760-778`）；资产出售时销售发票行的收入科目也取它（`sales_invoice_item.py:128-135`）。所以 1606 里只会留下净损益，不会有准则「转入清理 → 清理费用 → 变价收入」那些过程；而准则要求清理完毕后把这笔净损益转出（净损失转 `5711010`，净收益转 `5301010`）。也就是说上游记进去的这个数，正好就是准则要从 1606 转出去的那个数。
**选项：**

| 选项 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| A `5711010 非流动资产处置净损失` | 净损益直接进营业外支出，净收益记成负数 | 一步到位，满足上游过滤；弹簧厂处置旧设备多半是报废，以损失为主 | 有净收益时营业外支出出现负数（FD-017 已把这类 ≥ 式降为提示，不误报） |
| B `5301010 非流动资产处置利得` | 净损益进营业外收入，净损失记成负数 | 同上 | 损失为主的厂里，营业外收入会经常出现负数 |
| C 保留 `1606`，月末结转把余额转出 | 结转时按余额方向转到 `5711010` 或 `5301010` | 两个方向都落在准则规定的科目上 | 「清理完毕」要人来判断，结转凭证判断不了；要改结转凭证与状态检查，改动面大；上游过滤仍不满足 |

**用户回答：** 同 ①，属于授权范围。
**结论：** 取 **A**（DEC-123）。上游记的就是净损益，直接进损益类科目最贴近准则的结果；损失比收益常见，选支出科目时负数出现得最少。C 要让结转凭证去判断「清理完毕没有」，这件事系统判断不了，否决。

**③ 「上月未结」判到什么程度（FD-007）**
**提出者：** Claude
**背景：** 现在只查上月有没有有效的损益结转凭证（`closing.py:109-125`）。上月结转后又补录上月单据，本月照样能生成，补录的金额被算进本月。`month_closing_state()` 已经能判「结转后又有变动」和「结转后损益科目仍有余额」，只是生成前没有调用它。
**选项：**

| 选项 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| A 拦截：本年更早的月份凡 `complete=False` 都拒绝生成，并逐月列出原因 | 生成前逐月调 `month_closing_state` | 与报表说明行用同一套判断，不会一边说不完整、一边放行；原因写清，会计知道该取消重做哪个月 | 每次生成多查最多 11 个月（几十次聚合查询，可以接受） |
| B 只提示、不拦截 | 仍然生成，返回的 message 里列出不完整的月份 | 不挡会计 | 补录的金额照样被算进本月，FD-007 说的错数还在 |
| C 自动把补录差额结转到本月 | 生成时把以前月份的残留一并结平 | 不用逐月取消重做 | 本月 `3103` 增加额仍然不等于本月利润，SL-005 ① 不成立；跨月混账正是会计最忌的 |

**用户回答：** F 审核裁决「按建议来」，建议即「生成前对本年更早的月份调 `month_closing_state`，凡不完整即拒并列出」；本轮没有另外指示。
**结论：** 取 **A**（DEC-124）。DEC-121 照旧：没有损益发生额的月份算已结转、不拦。报错原文从「以下月份尚未结转」改为能区分「尚未结转」和「结转后又有变动」的新词条，因为后者说成「尚未结转」不真（需求 §4.11 第 4 条）。
