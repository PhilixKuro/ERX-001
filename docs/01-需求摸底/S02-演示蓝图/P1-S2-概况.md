## 本 Stage 的输入（S1 移交）

### 一、用户已裁决的方向（S1-R6 第 9、10 步，DEC-020~022）

**最优先需求（用户原话）**：**在客户面前跑通整个流程。**

三件事按序做，**次序本身是有理由的，不能重排**：

| # | 事 | 为何在这个位置 |
|---|---|---|
| 1 | **译名准确稳定** | 用户要求"不应该出现有些翻译了有些没翻译的情况"。**必须最先**——导航重整与按钮文案都要用到译名，反序会改两遍 |
| 2 | **导航重整** | 按业务流（接单→排产→领料→报工→入库→发货→开票→收款）重排入口。**前置**：LG-061 那个实测（改 `standard=1` 记录会不会被 `bench migrate` 覆盖）决定是"改记录（1 天）"还是"出 fixtures（3 天）" |
| 3 | **外部操控编排机制** | `PH-P1003`。供演示脚本 / MCP / React 前端三者共用，演示只是第一个用例 |

**远期**：全面重写 UI，**技术栈 React**。已查明**与近期工作无技术债传递**——desk 是 jQuery 不是 Vue，自建前端走 REST API v2，两套独立。

### 二、未裁决、A 步须处理的三件事

| # | 待定 | 选项已摆出 |
|---|---|---|
| 1 | **"界面自己动"走甲还是乙** | 甲=服务端推事件驱动（Claude 推荐：真正的外部操控、MCP 可复用、可拿手机当遥控器；代价是约百行前端监听）；乙=浏览器侧驱动（略简单，但控制权仍在 desk 内，MCP 与 React 复用不到驱动界面那部分） |
| 2 | **译名的目标侧术语标准** | **这是硬前置且须用户参与**（LG-070 缺口四）。缺它则清单补全了也定不了名。可选范围：先只统一"收付款方向"与"撞名"两类最确定的，行业术语留到实地考察后 |
| 3 | **演示要覆盖哪些环节** | 八步线性流程是用户举的例；但 S1 已知**质检、外协、月结完全未覆盖**，演示要不要包含它们未定 |

### 三、演示的三个已知雷（A 步须逐条定处置）

| # | 雷 | 后果 | 出处 |
|---|---|---|---|
| 1 | **工艺损耗不反算投料量** | 每张按 SO 生成的工单**必然短交**（SO 5000 支 + 5% 损耗 → 完工 4750）。"一路下一步"走到排产就会暴露，**UI 层补不了，要改服务端 mapper** | LG-039 / S1 概况 |
| 2 | **报工工时若填成默认或极小值，毛利率虚高 40 个百分点** | R3 实测工序成本记 0.27 元而非 433.3 元、毛利率 68.8% vs 应为 28.8%。**客户会看到漂亮但错误的成本数字，比不演示更糟** | LG-063 |
| 3 | **完工入库的额外费用科目须逐行手填**（N = 工序数 × 成本构成数，实测 11 行） | 演示时手填 11 行不可接受，且填错即成本进损益表 | LG-014 / `Company.expenses_added_to_stock_account` 出厂为空 |
