按该层级的四处差异：

| 项 | 本次取值 |
|---|---|
| 目标 | P1 剩余部分——**让客户演示能跑通** |
| 分解出 | 多个 Stage（S3 起，可能是原子或议题） |
| 议题形式 | `S{m}` 或 `S{m}G` |
| 非本级功能的去向 | **本 Phase 内的后续 Stage**——属规划产物，不经延迟需求 |
| 跨单位接口契约的家 | **本 Phase 概况**（[../P1-概况.md](../P1-概况.md)） |

### A 步产生的（R1，五条）

**一、两条次序约束（E/F 步排路线时必须遵守）**

1. **服务端修正必须在建样本数据之前**——工艺损耗不反算投料量、完工入库费用科目须手填这两个缺陷，会让建出来的样本数据**本身就是错的**（工单短交 250 支、费用科目进损益表）。**改完再建只建一次，反序要建两次。**

**二、建样本数据前须复核参数（不是"最好做"而是"不做会把错数字放进演示"）**

压簧/拉簧的国标参数表是 **B 级来源**且**同源页面内部有冲突**（d=5/D=30：661 vs 962；d=8/D=50：1154 vs 2203——摘要疑为跨行错位，该站表格系 OCR 转录、有已知错字）。**只需复核实际要用的那几行，不必复核全表。** 手段：与另一独立来源比对，或用弹簧刚度公式反算校验。

另：`12Cr18Ni9` **不对应** `SUS304`（它对应 SUS302/AISI 302；**SUS304 对应 `06Cr19Ni10`**）。填材料字段时别踩。

**三、中国科目表的同名父子结构会致选错科目，且改译名解决不了**（C 步定科目表方案时用）

zelin 的 4 张中国科目表里 **3 张有同名父子**（一般企业准则2024 **13 处**，含 `应收账款 > 应收账款` 11220/11221）。

**关键差别**：它**不会**触发官方那种"子科目被追加数字 `1`"——`add_suffix_if_duplicate` 的去重键是 `account_number + " - " + name.lower()`，科目号不同故键不冲突。**症状因此从"只差一个数字 1"变成"只差科目号前缀"**：下拉里 `11220 - 应收账款` 是 group、`11221 - 应收账款` 才能记账。

**故第 1 项（译名）解决不了这个风险，须在科目表设计时单独处理**（如给 group 层加「（汇总）」这类后缀）。

**四、做中国本地化的两条硬约束**（从 zelin 四处配置层缺陷反推，C 步定架构时用）

1. **科目号引用必须有一道机械校验**——遍历科目表验证每个被引用的科目号存在。zelin 缺这道，致其 `一般企业会计准则(2024)` 的示例配置 **144 个引用科目号命中 0 个**，且利润表示例的税金明细行**系统性错位 7 处**。
2. **不得把配置装载包在裸 `except` 里只写 log**——zelin 的 `setup_tax_template`/`setup_tax_rule`/`set_default_accounts`/`set_item_group_account` 全是这写法，**后果是建完公司看不出问题、做账时才发现**。

**五、~~`context` 判读规则~~（已作废）**

第 12 步③曾立："用了 `context` → 其翻译可当基线；没用 → 那两条撞名缺陷必然也没解决"。**该规则第 17 步①已作废**——`context` 是按 source + 场景**拆分**译文（解决"同一源词多义"），而撞名是**多个源词撞到同一目标词**，只能改其中一方的用词，`context` 帮不上。**保留此条是为防后续重新捡回这个错判读。**
