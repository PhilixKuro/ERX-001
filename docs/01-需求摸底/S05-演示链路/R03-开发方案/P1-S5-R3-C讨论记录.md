**③ 外网访问的连通方式**

**提出者：** Claude

**背景：** B 需求文档 §4.8 把「外网可达的方式」与「外网期间的访问控制、开放时段、是否关开发模式」留给 C 步，并要求显式写出取舍；不定下来，TS-012 的任务写不出来。局域网一段 Claude 先定为在实时端口前加一层转发、按来源补站点名请求头（不改上游源码），外网方案只决定「异地设备怎么到达本机的页面与实时两个端口」。

**选项：**

| 选项 | 描述 | 优点 | 缺点 |
|---|---|---|---|
| **A 私有组网（Tailscale，推荐）** | 本机与演示终端各装组网客户端、加入同一私有网络，终端用组网地址访问，路径与局域网相同 | 站点只对网内设备可达，口令风险小，可保留开发模式；外网与局域网共用一套机制；只在演示时段开客户端 | 终端要装客户端、登同一账号；国内能否稳定连上未验证 |
| B 临时外部隧道 | 本机跑隧道客户端得到一个外部地址，终端浏览器直接打开 | 终端免安装 | 站点外部可登录；只有一个入口，实时通道要改走同一入口、演示时须关开发服务器模式；须另做访问控制 |
| C 自建中转服务器 | 租一台云服务器做端口中转 | 国内最稳 | 要租服务器（有月费）；同样外部可达，访问控制另做；多一台机器要维护 |

**用户回答：** 选 A（选项工具作答）。

**结论：** **DEC-021**：外网环境下异地终端经**私有组网（Tailscale）**访问本机，与局域网共用同一套连通机制（实时端口前的转发层）。访问控制即组网成员资格＋Frappe 登录；开放时段即演示时开客户端；开发模式不关（理由：只有网内设备可达，报错页带堆栈的风险面同局域网）。国内可达性作为未验证的技术假设，实测不通时暂停交用户、改走 C。

#### 第 2 步：外网实测移出本 Stage

**提出者：** 用户

**背景：** 第 1 步的回复在写方案前被外部拦截截断，用户续发本条，并对外网一段给出新指示。

**用户回答：** 本 Stage 不做外网连通测试；在不实际测试的前提下，把「理论上能经 Tailscale 连上」的接口做好；等 S7 或 S8 做完后再测，有问题到时再修。

**结论：** **DEC-022**：
1. 本 Stage 的 CR-015 只实测**局域网**一种环境（DEC-017 三条照做）；**外网环境不实测**，更正 DEC-018 的「两种都验」。
2. 外网一段在本 Stage 交付到「理论上就绪」：连通机制本身与局域网共用、不另做；另交付组网环境的使用说明、连通检查工具（可在组网地址上原样运行）、以及实测前须做的准备清单（改管理员口令、外部探测只有两个端口可达等，即 B 文档 AC-009 的内容）。
3. 外网实测登为本 Stage 延迟需求（`SH-P1S5005`），唤醒条件「S7 或 S8G 收口后」，届时按 DEC-017 三条在组网环境实测，不通再修。
4. 连带：完成标志④改为「局域网环境下……」＋「组网接入的说明与检查工具已就绪」；B 文档 AC-004 只验局域网，AC-009 随延迟需求移后。路线文档 S5 行与 Stage 概况同步改写。
