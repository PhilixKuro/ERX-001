## 怎么用这份指南

**一、按「幕」组织。** 演示形态定为时间快进式（S8 概况「本 Stage 的输入」）：现场演示一段，再由生成器把场景时间推进几个月，接着演示。本稿把环节按幕分组，幕与幕之间标 **⏩ 快进点**。**本次实操不做快进**，所有单据都记在实操当天，快进点只是标出位置，供 A 步定 CR-008／CR-012 时用。

**二、计算层只验入口。** 安全库存、EOQ、覆盖 N 天要 90 天出库历史，SPC 要 25 个子组，一天的手工实操造不出来。这些环节**能点通、不报错就算过**，值为 0 或显示「样本不足」不算失败（用户 2026-10-18 裁决）。真实数值留给 CR-012 生成器去验。

**三、数字是演示用的〔典型值〕。** 物料规格、价格、工时沿用 S1 那套弹簧（压缩簧 2.0×16×50），只把订单量改成后面拆单、补货用得上的数。

**四、遇到问题不当场修，记进实操记录。** 记录放 `R02-人工实操/P1-S8-R2-Pai000实操记录.md`，一条一行：

「指南错」也记——本稿的字段位置和期望值大多来自读码，没上过浏览器（见回执「复核建议」）。这些记录是 R3 A 步需求讨论的输入，与 CR-003、CR-004、CR-008 等一起定。

# 准备

## P0　备份与启动

### 操作

1. 宿主机 Git Bash 先备份当前状态（实操后要回到这里）：

   ```bash
   docker/backup.sh
   ```

   记下新生成的时间戳。之后恢复清洁基准时**显式写** `docker/restore.sh 20261017_232126`——不带参数会取最新一套，也就是刚做的这份。

2. 另开一个终端跑 `docker/start.sh`，等 `bench start` 起来。浏览器开 `http://localhost:8000/desk`，用 `Administrator`／`admin` 登录。

3. **scheduler 保持关闭。** 本次的每日计算只靠环节 11、31 的「立即计算」手动触发，开了 scheduler 会在半夜自己跑一次，打乱对数。

### 数据模型

- 实时通道（socketio）经 `realtime-proxy` 转发到 9100 端口。页面长时间不自动刷新、右下角无实时提示时，先刷新页面；断开几秒后前端不会自己重连（项目概况「开发环境」节）。
- 本稿所有入口优先走首页「业务流程」图标进去的左侧栏（7 节 51 个入口）。**补货建议单、计件汇总单、产能负荷、SPC、员工以外的人事单据都不在侧栏里**，要用顶部搜索栏搜。

- 拆分数量与计件单价是 S7 加在 `BOM Operation` 上的两个字段，同一道工序不同产品可以拆法不同、单价不同。
