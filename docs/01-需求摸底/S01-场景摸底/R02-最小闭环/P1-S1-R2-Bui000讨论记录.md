## 演化过程

#### 第 1 步：干净弹簧厂环境的形态裁决（LG-005）

**来源项目：** ERX-001
**适用面·状态：** 仅本项目·已落地

**提出者：** Claude（R1 的 LG-005 明确把该项留给"最小闭环 build 步开工时定"）

**背景：** R1 的 DEC-011 定下"一律在新建的干净弹簧厂环境里做，不用 ERX Demo 演示数据"，但没定这个环境是**新建站点**还是**在现站点内新建公司**——R1 议题⑧选项 A 的原文是"另建站点或公司"，两者并列未选。该项直接决定操作稿第一环节怎么写（是"建站点+补 v16 初始化"还是"清 demo+建公司"），故按 `Bui000` 纪律 2 就地问清，不自拟。

R1 的 LG-005 还附了一句"`docker/` 脚本能力一句来自本轮之外的项目上下文，非本轮讨论内容"，即脚本到底支持什么当时未核实。本步先把事实基础查清再给选项。

**事实核实（本步新做，全部可复现）：**

| 查证项 | 结果 | 可复现路径 |
|---|---|---|
| 当前站点数据现状 | `erx.localhost`：Company 2（`ERX Demo` + `ERX Demo (Demo)`）、Item 10、Customer 3、Supplier 3、Sales Order 5、Warehouse 10、UOM 239、**BOM 0、Work Order 0**；默认公司 `ERX Demo (Demo)`；界面语言 `zh` | `docker compose -f docker/compose.yaml exec -T -w /workspace/frappe-bench/sites frappe ../env/bin/python -c "import frappe; frappe.init(site='erx.localhost'); frappe.connect(); print(frappe.db.count('Item'))"`（逐 DocType 计数）。**Windows 上须先 `export MSYS_NO_PATHCONV=1 MSYS2_ARG_CONV_EXCL='*'`**，否则 `-w /workspace/...` 被 MSYS 改写、报 `Cwd must be an absolute path` |
| Item / Customer / Supplier 有无 `company` 字段 | **均无**——这三类主数据**跨公司共享**，新建公司不会让它们从列表里消失 | `grep -c '"fieldname": "company"' erpnext/{stock/doctype/item/item.json,selling/doctype/customer/customer.json,buying/doctype/supplier/supplier.json}` → 三个 0；另以 `frappe.get_meta('Item').get_field('company')` → `False` 交叉确认 |
| Warehouse 有无 `company` | **有**，按公司隔离（现有 10 个仓库分挂两家公司各 5 个） | `frappe.get_all('Warehouse', fields=['name','company'])` |
| `seed-demo.sh --clear` 清掉什么 | 删 `(Demo)` 副本公司及其全部单据（经 Transaction Deletion Record，**异步任务**）+ 删 demo 主数据（item_group / item / customer_group / supplier_group / customer / supplier 六类，按 hooks 倒序）。**不动** UOM、Price List、Warehouse Type、全局币种——即 v16 那五处初始化缺口的成果**保留** | `erpnext/setup/demo.py:59-77`（`clear_demo_data`）、`:213-219`（`clear_masters`）、`:239-241`（`delete_company`）；清哪六类见 `erpnext/hooks.py:92-99`（`demo_master_doctypes`） |
| backup / restore 支不支持第二个站点 | 支持但须**显式传** `SITE_NAME`；而 `up.sh` 只建一个 `SITE_NAME` 站点、**不会建第二个** | `docker/backup.sh:13`、`docker/restore.sh:12`（均为 `SITE="${SITE_NAME:-erx.localhost}"`）；建站逻辑见 `docker/scripts/setup.sh:203-227` |

**选项：**

| 选项 | 描述 | 优点 | 缺点 |
|---|---|---|---|
| A 新建独立站点 | 建 `spring.localhost`，与 `erx.localhost` 完全隔离 | 彻底隔离，弄坏了不影响现站点；`bench drop-site` 可整站重来 | 新站点须自己补 v16 那五处初始化（fixtures / `stock_uom` / 价目表 / 全局币种 / `is_setup_complete`），而现有 `seed-demo.sh` 会连带建公司并导演示数据，须另写脚本或加开关；`up.sh` 不建它，换机器时会丢；backup/restore 每次须显式传 `SITE_NAME` |
| B 现站点新建公司，保留 demo | 在 `erx.localhost` 内建「弹簧厂」公司，demo 数据留着 | 零额外脚本；v16 初始化缺口已填好 | Item / Customer / Supplier 跨公司共享——选料号时 10 个 demo SKU 与 3 个 demo 客户混在列表里，违背 DEC-011「数据干净、出问题易定位」 |
| C 先清 demo，再现站点新建公司 | 跑 `seed-demo.sh --clear` 清 demo 公司与其主数据，删 `ERX Demo` 主公司，再建「弹簧厂」公司 | 满足 DEC-011 全部三条理由（干净 / 手建即学习 / backup-restore 可重置）；零额外脚本；v16 初始化成果保留；「建公司」「删公司」本身成了实操点 | `ERX Demo` 主公司须手动删；异步删除任务须等队列跑完才能确认清干净 |

Claude 推荐 **C**，理由：A 的隔离收益在当前阶段不值那份维护成本——现站点除 demo 数据外无需保护之物（项目尚未开始功能开发），而 A 要付出的是"脚本链以单站点为前提"这个实打实的缺口（`up.sh` 不建第二站点 → 换机器须手工重建 → README 记的五处 v16 初始化坑再踩一遍）。C 让 `backup.sh` / `restore.sh` 直接可用，DEC-011 说的"随时重置重来"不打折。B 由「Item / Customer / Supplier 无 `company` 字段」这条事实排除——那正是 NV-007 否决"在演示数据上学"的同一个理由。

**用户回答：** 选 C。

**结论：**
- 干净弹簧厂环境＝**在现站点 `erx.localhost` 内新建公司**，动手前先清掉 demo 数据与 `ERX Demo` 主公司。LG-005 就此关闭。
- 操作稿第一环节（原骨架的「建公司+科目表」）**前置一节「清场」**：跑 `docker/seed-demo.sh --clear`、确认异步删除任务跑完、删 `ERX Demo` 主公司，再建弹簧厂公司。这一节是对 R1 17 环节骨架的**增补**，非替换——增补理由是骨架成形时 LG-005 未裁决，当时无从写清场步骤。
- **A 与 B 均记入被否决表**（NV-011 / NV-012），理由同上。

## 遗留问题

| 事项 | 状态 | 触发条件（何时重新处理） |
|---|---|---|
| LG-011 `seed-demo.sh --clear` 的删除是异步的（走 Transaction Deletion Record + `start_deletion_tasks()`），须队列 worker 在跑才会真正执行 | 待验证 | 用户实操清场那一步时核实：跑完后查 `frappe.db.count('Sales Order')` 等是否真的归零；若队列未跑（`bench start` 未启动或 worker 挂了）会表现为"脚本说成功但数据还在"。操作稿已就此写入判据 |
| LG-012 `ERX Demo` 主公司能否直接删除未实测 | 待验证 | 清场那一步实操时验。它名下无单据（Sales Order 5 张全在 `(Demo)` 名下），理论上可删；但 ERPNext 删公司会连带删其科目表与仓库树，若有残留链接会报 LinkExistsError。操作稿已给出退路（删不掉则改名并停用，不阻塞后续） |
