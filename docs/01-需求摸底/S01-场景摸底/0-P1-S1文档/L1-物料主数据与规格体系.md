## 怎么读本层

前置是 [L0](L0-记账底座与组织骨架.md)——本层建的物料要引用 L0 的 UOM、物料组的默认值要引用 L0 的科目与仓库。

**五段结构**（DEC-008）与**两层深度**（DEC-010）同 L0。数值一律标 `〔典型值〕`（Stage 概况恒定约束）。

**本层与最小闭环操作稿的关系**：闭环环节 3、4 建过两个 Item 与一个 UOM，是"能跑就行"的最简形态。**本层把闭环有意跳过的三件事补上**：变体机制（规格爆炸的正解）、客户图号子表、物料价格的分层与时效。操作路径自成一体，不必跳读。

**产品族差异**（DEC-004）：本层是 A/B/C 三类产品族**差异最集中的两层之一**（另一层是 L2）。主线走冷卷圆簧（A 类），B 类异形线成型与 C 类板簧碟簧冲压的差异在段①末尾设专节。

## 段① 这一层要建什么

L1 的产物是**一份物料清册**：每个料号知道自己是什么、按什么单位存、属哪一类、多单位怎么换算、客户管它叫什么、卖多少钱。

顺序：

```
Item Group（物料组，树）        ← 先建，Item 必填它
  └─ item_group_defaults 子表  ← 该组下所有物料的默认科目与仓库
Item Attribute（变体属性）      ← 规格爆炸的解，Item 模板要引用
Item（物料）
  ├─ uoms 子表                 ← kg↔支 换算
  ├─ item_defaults 子表        ← 该物料的默认科目与仓库（覆盖组级）
  ├─ customer_items 子表       ← 客户图号 ↔ 内部料号
  └─ attributes 子表           ← 变体属性值（模板与变体各自填法不同）
Item Price（物料价格）          ← 挂价目表，L0 已建好价目表
```

### 第一步：物料组

搜「物料组」（Item Group）。**树形 DocType**（`is_tree=1`、`default_view='Tree'`，R5 实测），走树视图：`/app/item-group/view/tree`。

站点已有一棵默认树（`All Item Groups` 根下若干个）。弹簧厂要建的结构 〔典型值〕：

```
所有物料组（All Item Groups，根）
├── 原材料
│   ├── 弹簧钢丝        ← 65Mn / 60Si2Mn / 不锈钢丝
│   └── 辅料            ← 防锈油、包装material
├── 半成品
│   └── 卷制半成品      ← 回火前、表处前
├── 成品
│   ├── 压缩弹簧        ← 本稿主线
│   ├── 拉伸弹簧
│   ├── 扭转弹簧
│   └── 异形簧
├── 模具工装            ← 芯棒、凸轮、砂轮（场景 B4）
└── 询价件              ← 报价阶段建的料号（见下方说明）
```

建法：树视图点父节点 → 新建 → 填 `item_group_name`、按需勾 `is_group`。

**为什么要有「询价件」这一组**（对应场景 A1 的落地前提③）：报价时图号还没接单，而 BOM 必须挂已存在的 Item，故**询价阶段就要建料号**——这与厂里"接单才建料号"的习惯冲突。用独立物料组区分（或用 `Item.disabled`），是这处流程改造的技术落点。

**`item_group_defaults` 子表是本层第一个要理解的机制。** 它的类型是 `Item Default`（与 `Item.item_defaults` 同一个 DocType，R5 实测），字段含 `company` / `default_warehouse` / `default_price_list` / `expense_account` / `income_account` / `buying_cost_center` / `selling_cost_center` / `default_supplier` 等 19 个。

**在「原材料」组上填一行** 〔典型值〕：

| 字段 | 填什么 | 作用 |
|---|---|---|
| `company` | `华东弹簧`（必填） | 按公司分，多公司站点下同一组可有多行 |
| `default_warehouse` | `仓库 - HDS` | 该组物料默认收发哪个仓 |
| `expense_account` | `销货成本 - HDS` | 该组物料的费用科目 |

**这就是 L0 段②说的三级取值链的中间层**——比 Company 具体、比 Item 笼统。实际优先级见本层段②。

### 第二步：变体属性（本层的核心，闭环跳过了这一步）

场景 B6 的乱象原文是「每规格建一料号，几千料号失控」。**这正是 `Item Attribute` + `Item Variant` 要解决的问题**，R1 判它 ✅（原生够用）。

压缩弹簧的规格由五个维度决定 〔典型值〕：线径、外径、自由长度、总圈数、材质。前四个是**数值**，第五个是**枚举**。

搜「物料属性」（Item Attribute）→ 新建。

**数值型属性（四个）**，以线径为例：

| 字段 | 填什么 |
|---|---|
| `attribute_name` | `线径`（`autoname` 为 `field:attribute_name`，故即主键） |
| `numeric_values` | **勾上** |
| `from_range` | `0.3` |
| `to_range` | `12.0` |
| `increment` | `0.1` |

〔典型值：冷卷圆簧常用线径 0.3-12 mm，按 0.1 递增〕

勾了 `numeric_values` 后 `item_attribute_values` 子表不用填——取值由 from/to/increment 三个数确定。

四个数值属性按同法建 〔典型值〕：

| 属性 | from_range | to_range | increment |
|---|---|---|---|
| `线径` | 0.3 | 12.0 | 0.1 |
| `外径` | 2 | 200 | 0.5 |
| `自由长度` | 3 | 500 | 1 |
| `总圈数` | 2 | 50 | 0.5 |

**枚举型属性（材质）**：

| 字段 | 填什么 |
|---|---|
| `attribute_name` | `材质` |
| `numeric_values` | 不勾 |
| `item_attribute_values` 子表 | 逐行填，每行两个字段且**都必填**（R5 实测）：`attribute_value` + `abbr` |

| attribute_value | abbr |
|---|---|
| `65Mn` | `65MN` |
| `60Si2Mn` | `60SI` |
| `304不锈钢` | `304` |
| `琴钢丝` | `SWP` |

> **`abbr` 为什么必填、又为什么重要**：它是**生成变体料号时用的缩写**。机制在 `item_variant.py:496-527` 的 `make_variant_item_code()`——遍历变体的 `attributes` 子表，数值属性取**值本身**、枚举属性取 **`abbr`**，然后拼成 `模板料号-缩写1-缩写2-…`。
>
> 故 `abbr` 直接决定你的料号长什么样。**取短、取稳、取了别改**（改 `abbr` 会触发 `update_variant_item_codes_for_abbr_renames()`，`:199-218`，批量重命名变体料号）。

### 第三步：建物料模板

搜「`Item`」——**注意 v16 的 `Item` 未翻译**（R3 实测），搜中文「物料」搜不到。

**模板与普通物料的区别只有一个勾**：`has_variants`。

新建 → 填：

| 字段 | 填什么 | 说明 |
|---|---|---|
| `item_code` | `SPR-C`（压缩弹簧模板） | `autoname` 为 `field:item_code`（R5 实测），故即主键 |
| `item_name` | `压缩弹簧` | |
| `item_group` | `压缩弹簧` | 必填 |
| `stock_uom` | `支` | 必填。**定了尽量别改**，见段② |
| `has_variants` | **勾上** | 勾了它就成模板，不能直接用于单据 |
| `variant_based_on` | `Item Attribute`（默认值，R5 实测） | 另一个值是 `Manufacturer`——按制造商分变体，弹簧厂用不上 |
| `attributes` 子表 | 逐行加五个属性，**只填 `attribute` 列** | 模板不填 `attribute_value`（那是变体的事） |

**模板上填属性的另一种用法**：数值属性可在模板的 `attributes` 行上**收窄范围**——`Item Variant Attribute` 子表自己也有 `from_range` / `to_range` / `increment` 三个字段（R5 实测）。比如压缩弹簧模板把线径收窄为 1.0-6.0，而扭簧模板收窄为 0.5-3.0，各自从全局 0.3-12.0 里取一段。

### 第四步：生成变体

在模板页面点「创建变体」（Create Variant）。弹窗里为每个属性选值，确定即生成。

**生成的料号**（按上面的 `abbr` 规则）：线径 2.0、外径 16、自由长度 50、总圈数 8、材质 65Mn →

```
SPR-C-2.0-16-50-8-65MN
```

> **⚠ 批量生成有三档阈值，第三档是硬墙**（R5 实测 `item_variant.py:338-365` 的 `enqueue_multiple_variant_creation()`）：
>
> | 组合数 | 行为 |
> |---|---|
> | < 10 | 同步生成，立即返回 |
> | 10 - 599 | **走后台队列**（`frappe.enqueue`），返回 `"queued"`。**须 `docker/start.sh` 在跑**——这与 LG-011（清场走队列）、LG-051（`Bin` 重算）是同一个前提条件 |
> | ≥ 600 | **直接拒绝**，报 `Please do not create more than 500 items at a time` |
>
> **这对"规格爆炸"是实质约束**：弹簧厂五个维度全组合的理论值是天文数字（线径 118 档 × 外径 397 档 × …），**不可能也不应该全展开**。正确做法是**按实际接过的订单规格逐个生成**——变体机制的价值不是"预先生成所有可能"，而是"生成时料号自动规范、属性可检索、共用模板的 BOM 与工艺"。
>
> **报错文案里的 500 与代码里的 600 不一致**（`total_variants >= 600` 时报"不要超过 500"），是上游的文案疏漏。不影响功能，不入登记册。

### 第五步：建线材（普通物料，不走变体）

线材按 kg 采购、规格维度只有材质与线径两个，且数量有限，故**不必上变体**——直接建普通 Item。

| 字段 | 填什么 |
|---|---|
| `item_code` | `WIRE-65MN-2.0` 〔典型值〕 |
| `item_name` | `65Mn弹簧钢丝 φ2.0` |
| `item_group` | `弹簧钢丝` |
| `stock_uom` | `Kg` |
| `is_stock_item` | 保持勾选（`default=1`） |
| `is_purchase_item` | 保持勾选（`default=1`） |
| `is_sales_item` | **取消勾选**——线材不外卖 |
| `valuation_method` | 留空则用库存设置的全局值（本站点 FIFO）。**弹簧厂要按 FIFO**，因为线材存久了会锈（场景 F1） |

**`lead_time_days` 与 `safety_stock` 值得填** 〔典型值〕：线材采购提前期 7-15 天、安全库存按月用量的 15-20%。它们被 L5 的物料需求计划读取。本层可先留空，L5 会回来填。

### 第六步：kg↔支 换算（本层最重要的一个数字）

**这是 R1 给 L0 标的痛点「kg↔支 换算要设计」的落地处。**

在成品 Item（变体或单件）的 `uoms` 子表里加一行：

| `uom` | `conversion_factor` |
|---|---|
| `Kg` | `0.00868` 〔典型值〕 |

含义是**1 支 = 0.00868 Kg**（8.68 克）。

**这个数从哪来——展开长度公式** 〔行业通识，非本项目查证〕：

```
展开长度 L = π × 中径 D_m × 总圈数 n + 端部余量
             其中 中径 D_m = 外径 D − 线径 d

单支重量 W = L × 单位长度重量
             其中 单位长度重量 = π × (d/2)² × ρ      （ρ 为钢材密度，约 7.85 g/cm³）
```

本例代入 〔典型值〕：

| 项 | 值 | 算式 |
|---|---|---|
| 线径 d | 2.0 mm | 给定 |
| 外径 D | 16 mm | 给定 |
| 中径 D_m | 14 mm | 16 − 2 |
| 总圈数 n | 8 | 给定 |
| 展开长度 L | 约 352 mm | π × 14 × 8 = 351.9，端部余量约 0 |
| 截面积 | 3.14 mm² | π × 1.0² |
| 单支重量 | **约 8.68 g** | 352 × 3.14 × 7.85 / 1000 = 8.68 |

**故 `conversion_factor = 0.00868`。**

> **这个公式就是场景 A1 的「落地前提②」**：老师傅心里有数，要把它落成公式并录进系统。**ERPNext 不知道这个公式**——它提供了存放系数的地方（`Item.uoms`），但系数得你算。
>
> **第 ④ 阶段（客户定制）的一个具体二开点**：给 Item 加几个 Custom Field 存线径/外径/圈数，再用 hook 在保存时自动算出 `conversion_factor` 与 `weight_per_unit`。**这属"零风险高价值"的定制**——纯计算、不动核心逻辑、每个新料号省一次手算且不会算错。已并入 `SH-P1S1005` 的全量排查范围。
>
> **端部余量这一项是本公式最不确定的地方**：压缩弹簧的两端要不要加余量、加多少，取决于端部形式（并紧磨平 / 并紧不磨 / 开口）。本例按 0 算。〔未查证，实地考察时须向工艺员逐项校准〕

**另两个相关字段**：`weight_per_unit` = 0.00868、`weight_uom` = `Kg`。它们被物流与包装用（场景 F3 的支/盒/箱多层单位），与 `uoms` 子表是两套——**`uoms` 管"换算"，`weight_per_unit` 管"重量"**，弹簧的这两个数恰好相同是因为换算的目标单位正是重量单位。

### 第七步：客户图号（闭环跳过的第二项）

场景 A2 的乱象原文是「一物多码/一码多物，图号当品名用」，R1 判 🔧。

**原生的解是 `Item.customer_items` 子表**（类型 `Item Customer Detail`，R5 实测三个字段）：

| 字段 | 说明 |
|---|---|
| `customer_name` | Link 到 Customer |
| `customer_group` | Link 到 Customer Group（按客户组批量指定） |
| `ref_code` | **必填**，即该客户的图号 |

在成品 Item 上加行 〔典型值〕：

| customer_name | ref_code |
|---|---|
| `江南机械` | `JN-TH-0042` |
| `华威汽配` | `HW-SPR-118A` |

**作用**：销售单据上输入客户图号能反查到内部料号；打印出货单据时可显示客户图号而非内部料号。

> **这解决了"一码多物"但没完全解决"一物多码"**：同一支弹簧被三个客户用三个图号叫，子表三行即可（一物多码，✅ 解决）。**但反过来——同一个客户图号在厂里被建了三个料号**（因为三个业务员各建一次），子表管不住，那要靠 `ref_code` 的唯一性校验，而原生**没有这条校验**。
>
> 〔R5 未在 `Item Customer Detail` 上找到 unique 约束或 validate 方法，但**也未逐一排查 `item.py` 里是否有跨 Item 的 ref_code 查重**，故"原生没有这条校验"是**待查证**的推断。〕
>
> **判定维持 R1 的 🔧**：机制在、靠流程管住"谁能建料号"。若实地考察发现一码多物严重，加一条 `ref_code` 查重的二开成本很低（一个 `validate` hook）。

### 第八步：物料价格

搜「物料价格」（Item Price）→ 新建。`autoname` 是 `hash`（R5 实测），故主键无意义、靠字段组合识别。

线材的采购价 〔典型值〕：

| 字段 | 填什么 |
|---|---|
| `item_code` | `WIRE-65MN-2.0` |
| `price_list` | `Standard Buying` |
| `uom` | `Kg`（必填，R5 实测） |
| `price_list_rate` | `7.5`（元/kg） |
| `buying` | 由 `price_list` 带出 |
| `valid_from` | `default=Today`（R5 实测） |

> **`valid_from` / `valid_upto` 这两个字段是场景 A4（钢价联动调价）的关键**，R1 判 ✅。
>
> 钢价变动时**不改旧记录，而是新增一条带新 `valid_from` 的记录**——于是价格有了时间轴，历史单据取的是当时价、新单据取当前价。这比"改一个数"正确得多，也是"改价靠 Excel、改漏"这条乱象的原生解。
>
> **但它只解决一半**：改了线材价格**不会自动刷新已有 BOM 的成本**——那是 L2 的事（BOM 是快照），机制见 L2 段②。
>
> **`customer` / `supplier` 两个字段支持客户专属价**（R5 实测两字段都在）：同一料号可为不同客户建不同价格行。场景 A5（框架订单约定价）与 A4（客户专属价）由此落地，L4 会展开。

成品的销售价同法建，挂 `Standard Selling`、`uom` 填 `支`。

### 本层的 B/C 类产品族差异节（DEC-004）

主线是 A 类冷卷圆簧。B/C 两类在本层的差异如下：

#### B 类：异形线成型（扭簧、卡簧、线成型件）

| 维度 | 与 A 类的差异 |
|---|---|
| **变体属性** | 五个维度不够用。异形件的形状由**弯折点坐标序列**决定，无法用几个数值属性表达。**实际做法是按图号一件一料号、不用变体机制** |
| **kg↔支 换算** | 展开长度**不能用 π×D_m×n 公式**——要按图纸逐段量（直段 + 各弯角圆弧段）。故 `conversion_factor` 只能从图纸或试制实测得来 |
| **客户图号** | 比 A 类更重要——异形件几乎全是客户定制，图号是唯一的自然标识 |
| **物料组** | 建议独立一组「异形簧」，其下按客户或按用途再分 |

**故 B 类在本层的实际结论是：变体机制用不上，退回一件一料号；换算系数靠实测。** 这不是原生缺口——**任何 ERP 都无法从图纸自动算异形件展开长度**（那是 CAD 的事）。〔本判断属行业通识，未查证〕

#### C 类：板簧 / 碟簧（冲压成型）

| 维度 | 与 A 类的差异 |
|---|---|
| **变体属性** | 维度不同——板簧是厚度 × 宽度 × 长度 × 片数，碟簧是外径 × 内径 × 厚度 × 高度。**变体机制适用**，但属性集要另建一套 |
| **原材料单位** | 不是线材（kg/盘）而是**带钢或板材（kg/卷 或 张）**，换算是"每件用料面积 × 单位面积重量"而非展开长度 |
| **废料是产物** | 冲压的边角料有回收价值，**要建成一个 Item**（物料组「废料」），在 L2 的 BOM 里作 `secondary_items` 记入。A 类的切头切尾也有，但量小得多 |
| **模具** | 冲压模具是成本大头且有寿命，`模具工装` 物料组下的料号要带寿命字段（场景 B4，⚠ 需二开，属 L2/L7） |

**故 C 类在本层要多建一套变体属性 + 一个废料 Item。** 机制原生都有（`Item Attribute` 可建任意套、废料就是普通 Item），**无缺口**。

## 段② 背后的数据模型

### `Item`：`item_code` 即主键，改它等于重命名

- **`autoname` 为 `field:item_code`**（R5 实测），故料号就是主键。`item_name` 只是显示名、可随意改。
- **`track_changes = 1`**（R5 实测）：Item 的每次修改都生成一条 `Version` 记录，字段级 diff 可查。这是本层的一个白送的能力——**"谁把这个料号的 stock_uom 改了"有据可查**，在 `Version` DocType 里按 `ref_doctype='Item'` + `docname` 查。
- **`stock_uom` 是锚，且改它有代价**。三种误操作的后果（R3 读 `item.py` 查证）：

  | 动作 | 后果 | 位置 |
  |---|---|---|
  | 改 `uoms` 子表里 stock_uom 那行的 `conversion_factor` | **拦得住**，报 `Conversion factor for default Unit of Measure must be 1 in row {0}` | `item.py:456-460` |
  | 删掉那一行 | **自动补回**：保存时检查 stock_uom 不在 uoms 列表则 append 一行系数 1 | `item.py:401-412` |
  | **改 `stock_uom` 本身** | **整张 `uoms` 子表被清空**（`self.uoms = []`），只提示"请重新定义换算系数"。**已有库存记录时后果更重**——历史数量的含义变了 | 同上方法开头 |

  **计算不是"按第一行"，是按 `stock_uom` 字段。** 子表里 stock_uom 那行恰好排 idx 1 是 append 时机所致，"第一行"无特殊含义。

- **`is_stock_item`（`default=1`）是库存与非库存的总开关**。取消勾选则该物料不产生 `Stock Ledger Entry`、不参与估值——服务类、外协加工费这类要用它。弹簧厂的原材料与成品都要勾。
- **`include_item_in_manufacturing`（`default=1`）**：不勾则该物料不进 BOM 的物料清单。辅料（防锈油）若不想逐支核算可取消。
- **`end_of_life` 默认 `2099-12-31`**（R5 实测），到期后该物料不能用于新单据。停用旧规格时可用它，比 `disabled` 温和（`disabled` 是立即全禁）。

### 三级取值链的实际优先级（L0 段②的承接）

L0 说了有三级，本层给出确切顺序。取默认仓库/科目/成本中心时：

```
1. 单据行上已填的值             ← 最高，用户手填或上游单据带来
2. Item.item_defaults           ← 按 company 匹配的那一行
3. Item Group.item_group_defaults ← 同上，按 company 匹配
4. Company 上的对应默认字段      ← 兜底
```

**`Item Default` 这个 DocType 被两处复用**（R5 实测）：`Item.item_defaults` 与 `Item Group.item_group_defaults` 的类型完全相同，19 个字段一模一样。**这是 ERPNext 实现"分层默认值"的手法**——同一张表挂在不同层级上，取值时按层级顺序查。

**排查"这笔为什么记到了这个科目"就按这四级倒查。** 最常见的情形是第 3 级被忘了填、于是落到第 4 级的公司默认值上——症状是"所有物料的费用都记到同一个科目"。

### `Item Attribute` 与变体：三处关键机制

- **数值属性的校验**（`item_variant.py:107-131` 的 `validate_is_incremental()`，R5 实测）：

  ```python
  is_in_range = from_range <= flt(value) <= to_range
  remainder = flt((flt(value) - from_range) % increment, precision)
  is_incremental = remainder == 0 or remainder == increment
  ```

  即**既要在区间内，又要是 increment 的整数倍**（从 `from_range` 起算）。不满足则报 `Value for Attribute {0} must be within the range of {1} to {2} in the increments of {3} for Item {4}`。

  **`increment = 0` 会被单独拦住**（同函数开头），报 `Increment for Attribute {0} cannot be 0`——这是防 `ZeroDivisionError` 的防御性校验。

  **实际意义**：线径设 from=0.3 / increment=0.1 时，2.0 合法（(2.0-0.3)/0.1 = 17，余 0），而 2.05 非法。**故 increment 定得太粗会挡住真实规格**——实地考察时要问清厂里实际用到哪些线径档位再定。

- **变体料号的生成规则**（`item_variant.py:496-527`）：数值属性取值本身、枚举属性取 `abbr`，拼成 `模板码-缩写1-缩写2-…`。`item_name` 同法拼。**`abbr` 改名会触发批量重命名**（`:199-218`），故定了别改。

- **批量生成的三档阈值**（`:338-365`）：< 10 同步 / 10-599 走队列 / ≥ 600 拒绝。**第二档要 `docker/start.sh` 在跑**，与 LG-011、LG-051 同一前提。

- **变体与模板的关系是 `variant_of` 字段**（Link 到 Item）。变体继承模板的哪些字段由 `copy_attributes_to_variant()`（`:444-495`）决定——**不是全部继承**，而是按一张字段清单复制。故"改了模板，变体不跟着变"是常态，不是 bug。

### `Item Price`：`hash` 主键 + 时间轴

- **`autoname` 是 `hash`**（R5 实测），故主键无语义。识别一条价格记录靠 `item_code` + `price_list` + `uom` + `customer`/`supplier` + `valid_from` 这组字段。
- **必填只有四个**：`item_code` / `uom` / `price_list` / `price_list_rate`（R5 实测）。
- **`valid_from`（默认今天）+ `valid_upto`** 构成时效区间。取价时按单据日期落在哪个区间内取。**这是价格历史的正解**——不改旧记录、只加新记录。
- **`packing_unit`**：按包装单位取价（买一箱 vs 买一支价格不同）。场景 F3 的多层单位会用到，本层可留空。
- **`batch_no`**：按批次定价。线材按炉号进货且不同炉次钢价不同时用得上（场景 G1），本层留空。

### 本层各 DocType 的树形/非树形一览

| DocType | 树形 | 主键来源 |
|---|---|---|
| `Item Group` | **是**（`is_tree=1`、`default_view=Tree`） | `field:item_group_name` |
| `Item` | 否 | `field:item_code` |
| `Item Attribute` | 否 | `field:attribute_name` |
| `Item Price` | 否 | `hash` |
| `Item Variant Attribute` / `Item Customer Detail` / `Item Default` / `UOM Conversion Detail` | 否（皆为子表） | 子表无独立主键（`Item Customer Detail` 与 `UOM Conversion Detail` 为 `hash`） |

## 段③ 弹簧厂在这一层的场景

R1 给 L1 挂了两个场景：**A2**（定制件编码，客户图号 ↔ 内部料号）与 **B6**（规格变体爆炸）。本层另牵连三个。

### A2 定制件编码 🔧

**乱象原文**：一物多码/一码多物，图号当品名用。

**原生怎么接**：`Item.customer_items` 子表存客户图号（`ref_code` 必填），内部料号走自己的命名规则。销售单据可按客户图号反查料号，打印时可显示客户图号。

**效率收益**：业务员按客户的说法（图号）就能下单，不必记内部料号；同一支簧被三个客户叫三个名字，系统认得是同一支——**库存、BOM、工艺全部共用，不再重复建料**。

**落地前提（🔧 的原因）**：
1. **要先定内部料号的命名规则并守住它。** 本层给的规则是「变体机制自动生成」（`SPR-C-2.0-16-50-8-65MN`），它的好处是规则由系统执行、人守不住也不会乱。若厂里已有一套料号体系，得决定是迁过来还是并存。
2. **要管住"谁能建料号"。** 一码多物的根源是三个业务员各建一次，而原生**没有 `ref_code` 查重**（段①第七步已标为待查证）。靠权限（只让技术部建料号）比靠校验现实。
3. **询价阶段就要建料号**（场景 A1 的落地前提③在本层的落点）——用独立物料组「询价件」区分。

**原生缺口**：无结构性缺口。若实测确认无 `ref_code` 查重且实地考察发现一码多物严重，加一条 `validate` hook 成本极低。

**判定维持 🔧**。

### B6 规格变体爆炸 ✅

**乱象原文**：每规格建一料号，几千料号失控。

**原生怎么接**：`Item Attribute`（含数值型）+ 模板 Item（`has_variants=1`）+ 按需生成变体。料号自动规范、属性可检索、**变体共用模板的 BOM 与工艺**（L2 会讲变体如何共用 BOM）。

**效率收益**：
- 料号命名不再靠人，**同一规格永远得到同一个料号**——这是"失控"的直接解。
- 按属性检索：「所有线径 2.0 的压缩弹簧」一个筛选就出，而字符串料号做不到。
- 新规格 30 秒生成，不必抄一个旧料号改。

**落地前提**：
1. **定五个维度与各自的 from/to/increment。** increment 定粗了会挡住真实规格（段②已说明），定细了组合数爆炸。**要按厂里实际用到的档位定**。
2. **接受"按需生成"而非"预先全展开"**——600 组合的硬墙就是在逼你这样做。这需要一点观念转变：不是先把料号库建全再接单，而是接到新规格时生成一个。

**原生缺口**：无。**这是 R1 判 ✅ 且 R5 复查确认的一项。**

**但要指出一处 R1 没说的**：变体机制对 **B 类异形件不适用**（形状无法用数值属性表达），见段①的 B/C 差异节。**故 B6 的 ✅ 只对 A 类与 C 类成立**，B 类退回一件一料号——而那也不是缺口，是问题本身的性质决定的。

### 本层牵连的另外三个场景

| 场景 | 本层的落点 | R1 判定 |
|---|---|---|
| **A1** 按图询价 → 成本估算报价 | 「落地前提②」的展开长度公式在本层第六步落成 `conversion_factor`；「落地前提③」询价即建料号在第一步用独立物料组解决 | 🔧（主要工作在 L2 的 BOM 与机时费率） |
| **A4** 客户专属价与钢价联动 | `Item Price` 的 `valid_from`/`valid_upto` 时间轴 + `customer` 字段 | ✅（L4 展开） |
| **F1** 线材仓 FIFO 防锈 | `Item.valuation_method` 填 `FIFO`（或用全局默认） | ✅（L3 展开） |
| **F3** 成品仓多层单位（支/盒/箱） | `Item.uoms` 子表可加多行（支=1、盒=100、箱=1000）；`weight_per_unit` 供物流用 | ✅（L3/L4 展开） |

## 段④ 这一层的痛点与原生缺口

R1 给 L1 标的痛点只有一句：「**客户图号 ↔ 内部料号**」。R5 展开后判定维持 🔧，另补出三条 R1 没标的。

### 缺口一：客户图号 ↔ 内部料号 → **判定维持 🔧**

机制在（`customer_items` 子表），缺的是流程纪律与一条可能缺失的查重校验。详见段③的 A2。

### 缺口二（R5 新增）：展开长度公式无处存放，每个料号手算一次

**现象**：`conversion_factor` 是一个数字，ERPNext 不知道它从哪来。线径、外径、圈数这三个输入**在 ERPNext 里没有字段**——变体属性里有（`Item Variant Attribute.attribute_value`），但那是字符串、不是可参与计算的数值字段。

**后果**：每建一个新规格，有人要拿计算器按一遍公式，算错了没人发现（8.68 还是 8.86，系统都接受）。而这个数**直接决定 BOM 的材料成本**，算错即报价错、成本错。

**原生有没有解**：**没有**。ERPNext 不含任何行业公式引擎。

**判定**：⚠ **需二开，但成本极低、价值很高**。做法是给 Item 加三个 Custom Field（线径/外径/总圈数）+ 一个 `validate` hook 在保存时算出 `conversion_factor` 与 `weight_per_unit`。**纯计算、不动核心逻辑、零风险**。

**这是 R1 的 10 个 ⚠ 之外新增的一项**，且它**不在 52 场景里**——场景集是按"业务环节"设计的，而这一条是"一个数字的来源"，粒度更细。已并入 `SH-P1S1005` 的全量排查范围。**L10 汇总排优先级时应单列**：它是本项目目前发现的性价比最高的二开点（半天工作量，消除一类持续性错误）。

### 缺口三（R5 新增）：变体属性值不是数值，无法参与计算与范围查询

**现象**：`Item Variant Attribute.attribute_value` 的字段类型是 **`Data`**（R5 实测），即字符串——即便 `numeric_values` 勾上，存的仍是 `"2.0"` 这个字符串。

**后果**：
- **无法做范围查询**：「线径在 1.5 到 2.5 之间的所有压缩弹簧」写不出来（字符串比较会把 `"10.0"` 排在 `"2.0"` 前面）。
- **无法参与计算**：缺口二说的自动算 `conversion_factor`，取不到可靠的数值输入。

**这解释了为什么缺口二的二开要"另加 Custom Field"而不是"读变体属性"**——变体属性的值不可靠。

**判定**：⚠ **需二开**，与缺口二同批做（同一组 Custom Field 同时解决两个问题）。

〔**这一条的推断链有一处未验证**：R5 确认了 `attribute_value` 是 `Data` 类型，但**未实测**"按 attribute_value 做范围筛选实际会怎样"——理论上字符串比较会出错，但 Frappe 的报表层可能有类型转换。**实测办法**：建三个变体（线径 2.0 / 10.0 / 1.5），在 Item 列表按「变体属性」筛 `>= 2`，看 10.0 是否被正确包含。留给下一轮顺手做。〕

### 缺口四（R5 新增）：变体批量生成的 600 硬墙与队列依赖

**现象**：见段①第四步的 ⚠ 框。≥600 组合直接拒绝，10-599 走后台队列（须调度器在跑）。

**判定**：✅ **不是缺口，是正确的设计**。它在逼你"按需生成"而非"预先全展开"，而后者对弹簧厂本就是错的做法。

**但要记一条环境前提**：10-599 那一档依赖 `docker/start.sh` 在跑。**这与 LG-011、LG-051 是同一个前提条件**，三处同源——本项目凡走后台队列的功能都吃这个前提。**不入登记册**（同 LG-011 的处置），落在本层的操作提示里。

## 段⑤ 判定

**本层总判定：✅/🔧 为主，原生机制完备；新发现 2 个 ⚠ 且都是低成本高价值的二开点。**

逐项：

| 对象 | 判定 | 依据 |
|---|---|---|
| `Item Group` 树与分层默认值 | ✅ | 树形 + `item_group_defaults` 参与三级取值链，机制完整 |
| `Item` 主数据 | ✅ | 字段齐备，`track_changes` 白送审计能力 |
| **变体机制（A 类 / C 类）** | ✅ | 数值属性 + 自动料号 + 按需生成，**正是 B6 那条乱象的解**。R1 判 ✅，R5 复查确认 |
| **变体机制（B 类异形件）** | — | 不适用（形状无法用数值属性表达），退回一件一料号。**不是缺口** |
| kg↔支 换算机制 | ✅ | `Item.uoms` 是对的落点 |
| **展开长度公式的存放与计算** | ⚠ | **R5 新增**。无字段、无引擎，每料号手算。二开成本半天（3 个 Custom Field + 1 个 hook），价值高 |
| **变体属性值为字符串，不可计算/不可范围查** | ⚠ | **R5 新增**，与上一条同批解决。〔范围查的实际行为未实测〕 |
| 客户图号子表 | 🔧 | 机制在，靠流程管住建料号权限。`ref_code` 查重是否原生存在**待查证** |
| `Item Price` 与时间轴 | ✅ | `valid_from`/`valid_upto` + `customer`/`supplier`，价格历史与专属价都支持 |
| 变体批量生成的三档阈值 | ✅ | 正确设计。但 10-599 档吃"调度器在跑"这个前提（与 LG-011/051 同源） |

**交给下一层（L2）的四件事**：

1. **变体如何共用 BOM 与工艺**——本层生成了一堆变体料号，L2 要回答"是不是每个变体都要建一张 BOM"。
2. **`conversion_factor` 如何进入 BOM 的材料成本**——本层算出 0.00868，L2 讲它怎么变成"每支耗料 0.00868 kg × 7.5 元/kg"。
3. **改了 `Item Price` 为什么 BOM 成本不动**——本层第八步已埋了这个伏笔（BOM 是快照）。
4. **B/C 类的 BOM 结构差异**——本层给了物料侧的差异，L2 给工程侧（C 类有废料联产、B 类有程序而非模具几何）。

**留给 L10 汇总的**：本层产出 **2 个新 ⚠**（展开长度公式无处存、变体属性值非数值）+ **1 个维持的 🔧**（客户图号）。

**两个新 ⚠ 应作一组、且优先级高**——它们共用同一个二开动作（给 Item 加一组规格 Custom Field + 计算 hook），半天工作量，消除的是"每个新料号都可能算错一次"这类持续性错误。**这是本项目目前发现的性价比最高的二开点。**

**另须回填一条**：R1 的 52 场景里**没有覆盖"规格参数的存放与计算"这件事**——场景集按业务环节切，而这一条是数据粒度的。L10 排优先级时别因"不在 52 场景里"而漏掉它。
