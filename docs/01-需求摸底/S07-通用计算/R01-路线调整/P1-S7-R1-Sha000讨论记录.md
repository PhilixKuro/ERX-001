**⑤ 一年期演示场景**

**提出者：** 用户

**用户回答：** 要把一段长时间（比如一整年）的事件纳入演示：先正常找订单、接订单、按订单进料、生产、销售；然后按经济订货批量入料，同时接单生产销售继续发生；再加覆盖 N 天用量入料环节。总之要设计一个可信的长时间段场景，尽可能把各环节的各种可能都覆盖到——除了各种入料方案，还有根据订单自动选择利益最大化的工序、根据订单需求和损耗率反算生产计划之类，都应在演示中体现。

**结论：** 「100 条全链数据」改为「一年期场景」；三种补货规则**按阶段依次启用**（先按订单 → 加 EOQ → 加覆盖 N 天），让客户看到策略切换前后库存与资金占用的变化。产能负荷（IM-010）、控制图＋CPK（IM-011）、计件（IM-016）、损耗反算（CR-004）、自动选工艺（IM-018）都要在这一年里有对应单据；质检读数、报工工时、多 BOM 按真实分布造。

**⚠ 讨论中发现（Claude 按 ERPNext 机制推断，未实测）：一年场景对数据生成的四条约束**

1. **一年须是过去的一年**（如 2025-10～2026-09），由生成器按日期回填，演示当天从「今天」接着实时推。理由：系统不允许把库存单据记到未来日期。
2. **补货 daily 任务只看当下库存，不补跑过去的日子**。生成器须逐日推进模拟日期、自调三种补货逻辑，历史 Material Request 才有「当时为什么进这批料」的依据。⇒ **S7 的接口约束：补货计算须能接收一个「按某日计算」的参数**。
3. **回填过去日期的库存单据会触发库存成本重算排队**（repost），须严格按日期先后生成，不能乱序补单。
4. **账结法要做 12 次月末结转**，生成器按月调用。
