**② 四处「写方案时还得回头问用户」**

**提出者：** Claude

**背景：** 按 Spec 自评审第 5 条把 A 讨论当 C 步唯一输入自读，查出四处 A 步未裁或裁得不够细：

| # | 事项 | 为何须问 |
|---|---|---|
| a | 补货建议单一条的粒度 | DEC-001 写「每条建议一行：物料、仓库、规则…」，去重键却写「同物料同规则」，未含仓库；而 DEC-009 再订货点已按仓库算 |
| b | EOQ 的年需求 D | 第 2 步算式草案写「近一年出库量」，用户只裁了 2a～2c，未单独裁 D；与 90 天窗口（DEC-007／009）口径不一 |
| c | IM-018 选择日志 | 日志是方案 A（定时切默认）下 Claude 所提，用户改取 B 后延用，未单独表态（A 步复核建议 1） |
| d | IM-014 整条延迟 | 用户第 11 步问「能否单独延迟」并说「倒不如先不做」，随后两次「继续」是 API 报错重发、未再表态（A 步复核建议 4） |

**选项与用户回答：**

| # | 选项 | 用户选择 |
|---|---|---|
| a | 物料×仓库×规则（推荐）／物料×规则（全厂汇总） | **物料×仓库×规则** |
| b | 90 天日均×365 年化（推荐）／近 365 天实际出库 | **90 天日均×365 年化** |
| c | 写成工单评论（推荐）／独立日志表／不记 | **写成工单评论** |
| d | 确认整条延迟（推荐）／只是想问清目的，仍要做 | **确认整条延迟** |

**结论：**
- **DEC-021**：补货建议一条＝物料×仓库×规则；去重键同此；采纳生成的 MR 行带该仓库。理由：与 DEC-009 按仓库的再订货点同粒度。失效条件：客户集中一个仓库收料、按全厂汇总请购时。
- **DEC-022**：EOQ 的 D＝90 天窗口日均出库×365，与安全库存、再订货点同窗口同口径。理由：一年期场景第 3 个月起即有 EOQ；口径单一。失效条件：季节性明显、90 天年化失真时。
- **DEC-023**：选 BOM 日志写成该工单的一条评论（候选 BOM、各自单位成本、选中项），不新增 DocType。理由：演示可在工单时间线上讲；零新表。失效条件：要跨工单统计选择历史时。
- **IM-014 整条延迟经用户确认**，A 步复核建议 4 的疑点闭合；DEC-015 不变。
- **被否决**：a 的全厂汇总（与再订货点粒度不一）；b 的近 365 天实际出库（场景前几个月 D 偏小）；c 的独立日志表与不记。按 S6-R2 先例这三项不另编 NV 号，记在需求文档 §3.3 末行。
