## 一、任务总览

**一句话**：给 ERPNext 补上弹簧厂演示要讲的计算层——系统按三种规则算出「何时该进多少料」并交人定、按仓库自动维护安全库存与再订货点、出产能负荷与 SPC 控制图、按批次换算单位、工时与拆单解耦、工序间数量自动传递、计件额汇总进工资、建工单时按成本选 BOM，并给自有 app 的覆盖加一道迁移时自检。使用者是演示者（用户本人）与 S8 的一年期场景生成器；最终受众是弹簧厂客户的计划、仓库、车间与财务。

## 二、初始目的

**怎么提出的**：P1-S7-R1 路线调整中，用户要在客户演示里专门演示「系统知道何时该进多少料」（R1 DEC-001）。原计划放在演示之后的通用版计算层（原 S8G-S1～S3，IM-007～IM-016）因此整体提前到演示前，合并为本 Stage；同时新增两条需求——补货量规则 IM-017（「EOQ、覆盖 N 天用量、按订单进料三种可选、可多选，触发时由人决定是否按它下料」，R1 DEC-005／006）与按毛利自动选 BOM IM-018（R1 DEC-008）。S8 的一年期演示场景要按阶段依次启用三种补货规则（按订单 → 加 EOQ → 加覆盖 N 天），并让计算层每一项都有对应单据（R1 DEC-007／010）。

**要解决的核心问题**：ERPNext v16 有记录层、缺计算层（需求图谱 §7.5）。

- **补货**：原生能在库存低于 `Item Reorder` 的再订货点时自动建 Material Request，但再订货点与再订货量都是人填的固定值；推荐再订货点的算法在报表里却不回写（`itemwise_recommended_reorder_level.py:29`）；`Item.safety_stock` 全库无一处计算；「进多少」没有任何算法。开了原生自动建单，它会直接提交 MR（`reorder_item.py`），与「交人决定」冲突。
- **生产**：产能这一维没有参与任何计划层计算，22 个原生报表无一是负荷口径；`Quality Inspection Reading` 的读数只用于单次判合格，没有跨批次统计；kg↔pcs 系数是物料级固定值，同规格不同批次钢丝给不出不同系数；工时基准量与拆单共用一个勾选，表达「每 100 支 40 分」就被迫每 100 支开一张 Job Card；三道工序的 Job Card 数量相同，前道损耗不传给后道，后道操作工须手填差额才能提交。
- **人工与成本**：`Job Card Time Log` 已有员工、工序、完工数，但薪资公式读不到它；建工单取哪个 BOM 只认人设的默认值，料价工价变了不会跟。
- **守护**：自有 app 的覆盖靠装载末位与 whitelisted 覆盖生效，`check_app_order()` 在 S5 已写好，却没有任何调用方，将来装别的 app 挤掉覆盖不会有人知道。

**用户在 A 步的取舍倾向**：凡「看起来过于复杂专业、落地难培训」的（IM-014）宁可先不做；凡用户缺业务知识无法判断的（IM-012 场景、提前期口径），按 Claude 的倾向先做、把另一选项登记为延迟需求，等 IM-003 摸底答回再修正。

### 3.3 被否决方案记录

| 编号 | 方案 | 否决理由 |
|---|---|---|
| NV-001 | 草稿 MR 承载补货建议 | 三规则同触发即三张草稿难比；草稿不计入计划量（`get_indented_qty` 只计 `docstatus=1`）致天天重复；依据只能塞备注 |

### 4.2 补货（IM-017，TS-003／007；DEC-001～006／021／022）

#### 4.2.1 补货建议单（新 DocType）

一条记录是**某物料在某仓库、按某条规则、在某计算日给出的一条建议**（DEC-001／021）。

| 字段 | 含义 |
|---|---|
| 物料、仓库、公司 | 建议的对象；仓库取该物料 `Item Reorder` 行的仓库（EOQ、覆盖 N 天）或销售订单／生产计划的供料仓（按订单，C 步定取法） |
| 规则 | EOQ／覆盖 N 天／按订单，三选一 |
| 计算日期 | 本次计算的日期 D（§4.13） |
| 建议量 | 按 §4.2.3 算式；单位为物料的库存单位 |
| 触发依据 | 当时计划量及其构成（实际库存、已订、已请购、已预留，取自 `Bin`）、再订货点、算式的每个输入值与中间结果——足以让人手算复核 |
| 状态 | 待定／已采纳／已忽略 |
| 生成的 MR | 采纳后回填 |
| 来源单据 | 按订单规则：触发它的销售订单（可多张，C 步定子表或文本） |

**去重**（DEC-001／021）：同一 物料×仓库×规则 已有「待定」建议时，再次计算**更新**该条（计算日期、建议量、触发依据），不新增。已采纳或已忽略的不受影响，下次触发另建一条。某次计算判定不再触发时，已有的待定建议**保留不动**（不自动撤销；C 步可加「已过时」标注，不改状态取值域）。

**采纳**：人在建议单上点「采纳」（可改建议量后再采纳）→ 生成一张 Material Request（类型取该物料 `Item Reorder` 行的 `material_request_type`；无该行的按订单建议取「采购」）、**提交**，MR 回指建议单（字段或 `ref`，C 步定），建议单状态改「已采纳」并回填 MR。**忽略**：状态改「已忽略」，不生成任何单据。列表视图支持多选批量采纳／忽略（C 步可定为不做，须在方案里写明）。

**同物料多规则并列**：三种规则同时触发时出三条建议，并列可比、不合并、不排优先级（R1 DEC-006）。

#### 4.2.2 参数（TS-003；DEC-004）

| 参数 | 公司默认 | 物料覆盖 | 用于 |
|---|---|---|---|
| 每次订货成本 S（元） | 有 | 有 | EOQ |
| 年持有成本率 h（%） | 有 | 有 | EOQ（H＝`valuation_rate`×h） |
| 覆盖天数／盘点周期 N（天） | 有 | 有 | 覆盖 N 天 |
| 盘点起算日 | 有 | 无 | 覆盖 N 天 |
| 服务水平（%） | 有，默认 95 | 有 | 安全库存 |

物料覆盖为空即取公司默认。物料上另有：三个**规则启用勾选**（EOQ／覆盖 N 天／按订单，可同时勾）、**「自动计算补货参数」勾选**（管 §4.3、§4.4 是否回写，DEC-009）。公司默认放 Company 上的 Custom Field 还是一张自有设置单，C 步定。

#### 4.2.3 三种规则（DEC-003／006／022）

公共口径：**日需求**＝某日该物料在该仓库的出库量之和（领用＋发货，即 SLE 中 `actual_qty<0` 的库存出库类型，具体 `voucher_type` 范围 C 步定、须与 §4.3 的 σ 完全同口径）；**取样窗口**＝(D−89, D] 共 90 天，**含零出库日**；**日均用量 d̄**＝窗口内日需求之和÷90；**提前期 LT**＝`Item.lead_time_days`（DEC-008）；**计划量**＝原生 `Bin.projected_qty`（实际＋已订＋已请购＋计划生产−已预留等，原生口径不改）。

| 规则 | 触发 | 建议量 |
|---|---|---|
| **EOQ** | 计划量 ≤ 该仓库 `Item Reorder.warehouse_reorder_level` | √(2·D_年·S/H)，D_年＝d̄×365（DEC-022），H＝`valuation_rate`×h；结果向上取到 `min_order_qty`（为 0 则不取整） |
| **覆盖 N 天** | (D − 盘点起算日) mod N ＝ 0 | 目标量＝d̄×(N＋LT)＋`safety_stock`；建议量＝目标量−计划量；≤0 不出建议 |
| **按订单** | 存在未覆盖的销售订单使该物料有净缺料 | 未交销售订单经 BOM 展开的净缺料（复用原生 `production_plan.py:1745 get_items_for_material_requests` 的算法），**BOM 取 §4.10 共用选 BOM 函数的结果**（DEC-019） |

- EOQ 的 D_年、S 或 H 任一为 0 或缺失时不出建议，并在当次计算结果里记一条「参数缺失」（不报错、不中断其它物料）。
- EOQ 只对有 `Item Reorder` 行的 物料×仓库 计算（触发线来自该行）；覆盖 N 天对勾了该规则且有 `Item Reorder` 行的计算（仓库来源，C 步可放宽为「物料默认仓库」，须写明）。
- 按订单的「未覆盖」：已有已提交 MR／PO 覆盖的缺料不重复建议；净缺料算法沿用原生已扣减的部分，C 步核原生函数实际扣了哪些、在方案里写明。

#### 4.2.4 原生自动建单关闭（DEC-002）

`Stock Settings.auto_indent` 保持 0；演示站与测试站的配置脚本**显式置 0**（实测演示站当前为 0，A 步第 2 步）。原生 `reorder_item` 的 daily 任务保留不删，它在 `auto_indent=0` 时不建单。`Item Reorder.warehouse_reorder_qty` 本 Stage 不再被任何触发路径使用，字段保留、不清空。

#### 4.2.5 交人决定

系统**不自动成单**，只建补货建议单（R1 DEC-006）。演示讲法：同一物料三条建议并列，人看触发依据、比建议量，选一条采纳。

### 4.3 安全库存（IM-009，TS-004；DEC-007）

**safety_stock ＝ Z × σ × √LT**

- **Z**：由服务水平按标准正态分布分位数换算（95% → 1.645；A 步记作 1.65，实现取精确分位数，C 步定用 `statistics.NormalDist` 或查表）。
- **σ**：§4.2.3 同一 90 天窗口的日需求样本标准差（含零出库日；总体或样本标准差 C 步定、在方案里写明）。
- **LT**：`Item.lead_time_days`（天）；为 0 或空时 safety_stock 记 0 并在计算结果里记「提前期缺失」。
- **按什么粒度**：`Item.safety_stock` 是物料级单值，故 σ 按**全部仓库合计**的日需求算（与 §4.4 按仓库不同，这是原生字段形状决定的；见 RS-005）。
- **写入**：只对勾了「自动计算补货参数」的物料写 `Item.safety_stock`；未勾的人填值不动。
- 计算顺序在再订货点之前（§4.12）。

### 4.4 再订货点回写（IM-008，TS-005；DEC-009）

对勾了「自动计算补货参数」的物料，逐条已有的 `Item Reorder` 行：

**warehouse_reorder_level ＝ d̄_仓 × LT ＋ safety_stock**

- d̄_仓：该行 `warehouse` 的 90 天日均出库（§4.2.3 口径，按仓库过滤 SLE）。行上 `warehouse_group` 有值时是否把组下仓库合计，C 步读原生 `reorder_item.py` 对该字段的用法后定。
- safety_stock：§4.3 刚写入的物料级值。
- **只更新已有行、不自动建行**（仓库与请购类型是业务选择）；物料勾了但无 `Item Reorder` 行的不处理、不报错。
- 与原生报表 `itemwise_recommended_reorder_level` 的数字不一致是预期的（原生按物料不分仓库、窗口任意），演示与复核时须说明。

### 4.5 提前期单向同步（TS-003；DEC-008）

- 单位成本＝(`raw_material_cost`＋`operating_cost`)÷BOM `quantity`÷(1−`process_loss_percentage`/100)。计算前按各 BOM 的 `rm_cost_as_per` 刷新原料价（调原生 `update_cost`，是否落库存盘 C 步定；要求选择用的是刷新后的价）。工价取工作中心 `hour_rate`；**不含**计件单价。
- 取最低者；并列时取原生默认 BOM，再并列取名称序第一个（C 步可定其它确定性规则，须写明）。

**三处调用**（DEC-019）：
1. **工单新建**：Work Order `before_insert`／`validate`（新建时）——若 `bom_no` 仍等于原生带出值（即未被人改过），替换为函数选中项；若已被人改过，不覆盖，在表单提示「按成本推荐的是 X（单位成本 …）」。「未被人改过」的判据 C 步定（如比对原生 `get_default_bom` 的结果）。销售订单建工单（`sales_order.py:1830 make_work_orders`）与生产计划建工单都经新建 Work Order，故一并被覆盖。
2. **IM-017 按订单展开**：§4.2.3 按订单规则展开原料用此函数的 BOM。
3. **生产计划带 BOM**：Production Plan 的 `po_items.bom_no` 带出时用此函数（`get_item_details` 路径；挂法 C 步定，不得用类覆盖），使生产计划算缺料（`production_plan.py:458 get_mr_items` 起）与工单一致。

#### 4.11.2 SPC 控制图与过程能力（IM-011，TS-012；DEC-012）

**数据**：`Quality Inspection`（`docstatus=1`）的 `readings` 子表；一行（某检验单×某参数 `specification`）＝**一个子组**，读数取 `reading_1..reading_10` 中能转为数字的值（字段是 `Data` 字符串，非数字值剔除并计数）；规格上下限取该行 `min_value`／`max_value`。

**筛选**：物料、检验参数必选；日期区间（`report_date`）、检验类型、工作中心（经 `reference_type`＝Job Card 取其 `workstation`）可选。子组按 `report_date` 再按检验单名排序。

**计算**：
- 每组 X̄、R（n≥2）；X̿＝组均值之均值；R̄＝n≥2 各组 R 之均值。
- σ_组内＝R̄/d₂；子组大小不一时按每组 n 取 d₂（内置 n＝2…10 常数表），实现口径（如各组 R/d₂(n) 的均值）C 步定并在方案里写明公式。
- σ_总体＝全部读数的样本标准差。
- **Cpk**＝min(USL−X̿, X̿−LSL)÷(3σ_组内)；**Ppk** 同式用 σ_总体。只有单侧限时取单侧。**n＝1 的组只进 Ppk**，不进 X̄-R 与 Cpk。
- 控制限：UCL／LCL＝X̿±A₂·R̄（或 3σ_组内/√n，按每组 n），中心线与 ±1σ／±2σ／±3σ 区按本次筛选范围内数据算，不设控制限冻结期。
- 不足 **25 个**（n≥2 的）子组时照常出数，摘要标「样本不足、仅供参考」。

**Nelson 8 条**（作用于 X̄ 序列，每点标出触发了哪几条）：
1. 1 点落在 ±3σ 之外；
2. 连续 9 点在中心线同侧；
3. 连续 6 点单调递增或递减；
4. 连续 14 点上下交替；
5. 连续 3 点中有 2 点落在同侧 2σ 之外；
6. 连续 5 点中有 4 点落在同侧 1σ 之外；
7. 连续 15 点都在 ±1σ 之内；
8. 连续 8 点都在 ±1σ 之外（两侧均可）。

**呈现**：
- **Script Report**：顶部摘要（Cpk、Ppk、子组数、读数数、剔除的非数字读数数、判异点数、样本不足标注）；表格一行一个子组（日期、检验单、n、X̄、R、触发规则）；附原生折线图（X̄ 与 UCL／CL／LCL）。
- **控制图 Page**（自有页面）：同一筛选与计算（调同一后端函数），用前端图表库画 X̄ 图，**判异点逐点着色**、悬停显示触发规则；可从报表跳转。页面文案进 csv。图表库在 frappe 自带 `frappe-charts` 与 Insights 前端带的 `echarts` 间选，C 步先核能否逐点着色（RS-004）；若引入新前端依赖，须锁版本并走 app 自己的构建。

#### 4.11.3 批次级单据单位换算（IM-012，TS-008；DEC-013）

- **字段**：`Item` 加「单支展开长度（m）」；`Batch` 加「线密度（kg/m）」。
- **系数**：某批次的 kg↔pcs 系数＝单支展开长度×线密度（kg／支）。物料的 UOM 换算方向（库存单位是 kg 还是 pcs、交易单位是哪个）按该物料 `UOM Conversion Detail` 的既有配置，系数按方向取它或其倒数，C 步定换算方向判定。
- **生效**：单据行选了 `batch_no` 且该批次有线密度、物料有展开长度时，行的 `conversion_factor` 取批次系数；否则回落物料级（`get_conversion_factor`，`get_item_details.py:1619`）。
- **范围**：至少覆盖采购收货、库存凭证（领料）、发货三类单据行；`Sales Order`／`Purchase Order` 行无批次，不涉及。原生行上批次字段受 `Stock Settings.use_serial_batch_fields` 影响（关闭时批次在 `serial_and_batch_bundle` 里），C 步先核演示站该设置与取批次的路径。
- **手段**：`get_conversion_factor` 不接收批次、被多处直接 import（A 步第 8 步），**不覆盖它**；改为在单据行选批次后由前端调自有 whitelisted 方法取系数，并在服务端 `validate` 复核一次（`doc_events`）。具体挂点 C 步定。
- 场景②（领料／BOM 用量按批次线密度重算每支实耗）不做（`SH-P1S7004`）。

**⚠ 依据最弱**：用户无业务知识可参考，按 Claude 倾向只做单据单位换算。摸底问点清单加一问（§4.16）。

## 七、预期使用流程

**仓库／计划员（演示者扮演）**

1. 在公司上填补货默认参数（订货成本、持有成本率、N、起算日、服务水平）；在物料上勾要用的补货规则与「自动计算补货参数」，个别物料覆盖参数。
2. 每天早上（或演示时按「立即计算」）系统依次算安全库存、再订货点、三规则建议。
3. 打开补货建议单列表，按物料看并列的建议：每条显示规则、建议量、触发依据。
4. 选一条点「采纳」（可先改量）→ 系统生成并提交 MR；其余点「忽略」或留待定。

**生产计划员**

1. 建工单（手动、从销售订单或生产计划）：勾了按成本选 BOM 的物料自动带出单位成本最低的 BOM，工单评论里有候选与成本；想用别的 BOM 就手改，系统只提示推荐项。
2. 打开产能负荷报表，按周看各工作中心负荷，标红的桶是超载。

**车间**

1. 前道 Job Card 报工提交后，后道未开工卡数量自动变为前道完工数；操作工不再手填差额。
2. 每 100 支 40 分的工序，一张工单只出一张卡（除非 BOM 工序上填了拆分数量）。

**质检**

1. 检验单照常录读数。
2. 打开 SPC 报表或控制图页面，选物料与参数，看 Cpk／Ppk 与判异点。

**财务／人事**

1. 月末按员工生成计件汇总单（或由 S8 调用），核对明细后提交 → 自动生成 `Additional Salary`，进当月工资单。

**仓库收发（单位换算）**

1. 采购收货、领料、发货的行上选了批次，换算系数自动取该批次的值。

**实施者（D 步）**

1. TS-001 单独提交后再开功能任务。
2. 新 DocType、字段、页面每加一处即补 csv 并跑译名自检（开发守则）。
3. 每个覆盖上游行为的挂点当次登记进 README 覆盖登记节。

## 九、术语定义

| 术语 | 定义 |
|---|---|
| 补货建议单 | 本 Stage 新建的 DocType，一条＝某物料在某仓库按某规则在某计算日给出的一条进料建议 |
| 计划量 | 原生 `Bin.projected_qty`（实际＋已订＋已请购＋计划生产−已预留等），不改原生口径 |
| 日需求 | 某日某物料（在某仓库）的出库量之和（领用＋发货），无出库的日子记 0 |
| 取样窗口 | 以计算日 D 为终点的 90 天 (D−89, D] |
| 计算日 D ／ 按某日计算 | 每日计算与计件汇总的日期参数；只定窗口终点、盘点日判定与单据日期，库存状态取调用当下（§4.13） |
| 自动计算补货参数 | 物料上的勾选，管安全库存与再订货点是否被每日回写 |
| 盘点日 | 覆盖 N 天规则下 (D−起算日) mod N＝0 的日子 |
| 后道未开工卡 | 某工单下一道工序上尚未开工的 Job Card（判据 C 步定） |
| 单位成本（选 BOM） | (原料成本＋工序成本)÷BOM 数量÷(1−损耗率)，不含计件 |
| 子组 | SPC 中一张检验单的一个检验参数的一组读数 |
| 计件汇总单 | 本 Stage 新建的 DocType，某员工某期间计件额的汇总与来源明细 |
| 生产增强 | `frappe_china` 新增的第 2 个模块 |
