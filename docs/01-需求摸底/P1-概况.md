## 本 Phase 开发范围

**双重目的**（S1-R1 讨论后明确，对应四阶段战略第 ① 阶段）：

1. **学会用 ERPNext**——执行者（用户）业务零基础、仅有软件工程知识，需通过实操跑通弹簧厂全链业务建立能力。
2. **摸清原生适用边界**——哪些环节原生够用、哪些靠培训与流程改造、哪些必须深度二开。

两者由同一份产物承载：L0-L10 分层学习路径，每层五段（该层要建什么 / 背后的数据模型 / 弹簧厂在这层的场景 / 该层痛点与原生缺口 / 判定）。学与摸底是同一份材料的两面。

**背景约束**：客户规模未知、需求未明确、未实地考察，且**项目内无任何弹簧资料**（场景集按行业通识生成，其数值只具行业典型值效力）。本 Phase 不产代码，只产判断依据与学习材料。

**新的最优先目标（用户原话）**：**在客户面前跑通整个流程。** 为此三件事按序做——① **译名准确稳定**（"不应该出现有些翻译了有些没翻译的情况"）；② **导航重整**（按业务流重排入口）；③ **外部操控机制**（供演示脚本 / MCP / React 前端共用）。**远期全面重写 UI，技术栈 React。**

**故本 Phase 的收口标志改为**：S2 的 `devBlueprint` 产出需求图谱 + 架构 + 路线，把"客户演示要什么"分解为可开工的 Stage 序列。**②③ 两项转为 S2 需求讨论的输入**——演示需求本身就要重排一次优先级，按新口径处理比在 S1 内按旧口径补完更合理。

**收口标志第 ③ 项的进度**（R5 推进一项）：LG-021 证明 R1 的 ⚠ 判定因"grep 未找到即推定缺口"而偏严，该风险**已应验三次且全部是"范围缩小"方向**——D2（R3，`fixed_time` 原生存在）、中国科目表（R5，`unverified/` 下有一份 82 节点的 2006 准则版）、B1（R5，BOM 版本管理原生完整故 ⚠ 拆半）。

**故余下 4 项未读源码的 ⚠**（B4 模具工装 / E7 SPC・CPK / F5 寄售 VMI / H7 银行对账）**预计仍有 1-2 项会缩小或改判**。~~应在各自所属层产出时逐项复查~~ → **该安排已失效**（L3-L10 暂停），改由 S2 的需求讨论按新口径处理。

**R6 另证明这条教训有镜像形态**（S1 概况 LG-067）：LG-021 是"查不到就推定没有"，R6 三次判错导航是"**查到一张名字像的表就推定它是那个东西**"。两者同源——**拿间接证据当直接证据**。故此后凡断言界面呈现，须数据层与渲染层两层都有依据。

**⚠ 清单本身也在增长**：R5 新增 5 项待排序（展开长度公式无处存放、变体属性值非数值、`Routing` 无基准量、`setup_time` 缺失、图纸文件版本与通知），其中**前两项不在 R1 的 52 场景里**（场景集按业务环节切，这两条是数据粒度的），**后两项是 C3/C4 两个最高优先级 ⚠ 的共同前置**。排序时须把"前置型"与"并列型"分开看，详见 [S1 概况](S01-场景摸底/P1-S1-概况.md) 的 LG-054・LG-055。
