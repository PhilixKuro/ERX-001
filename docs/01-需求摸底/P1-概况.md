## 本 Phase 开发范围

**双重目的**（S1-R1 讨论后明确，对应四阶段战略第 ① 阶段）：

1. **学会用 ERPNext**——执行者（用户）业务零基础、仅有软件工程知识，需通过实操跑通弹簧厂全链业务建立能力。
2. **摸清原生适用边界**——哪些环节原生够用、哪些靠培训与流程改造、哪些必须深度二开。

两者由同一份产物承载：L0-L10 分层学习路径，每层五段（该层要建什么 / 背后的数据模型 / 弹簧厂在这层的场景 / 该层痛点与原生缺口 / 判定）。学与摸底是同一份材料的两面。

**背景约束**：客户规模未知、需求未明确、未实地考察，且**项目内无任何弹簧资料**（场景集按行业通识生成，其数值只具行业典型值效力）。本 Phase 不产代码，只产判断依据与学习材料。

| 原记载 | 复核结论 |
|---|---|
| **`Routing` 无基准量** | **不成立。** `BOM Operation.batch_size`（Float，default 1，`fetch_from: operation.batch_size`）**就是 MRP II 意义上的工时基准量**，且在工时路径被真实消费——`work_order.py:1490-1497`：`if not d.fixed_time:` 时若 Operation 勾了 `create_job_card_based_on_batch_size` 则 `qty = d.batch_size`，随后 `time_in_mins` 除以（exploded 时乘以）它。单测佐证 `time_in_mins=40, batch_size=5` → WO qty=1 得 8.0、qty=5 得 40.0。**"每 100 件耗时 X"原生可表达。**<br>**真缺口小得多且换了性质**：工时基准量与任务单拆批粒度**共用同一个开关**，要"每 100 支 X 分"就被迫每 100 支开一张 Job Card（`work_order.py:2902-2910`）。**是耦合缺陷，不是能力缺失。**<br>**当初为何判错**（三因叠加）：① 上游 `Operation.batch_size` 带 `depends_on`，不勾开关界面不显示；② `BOM Operation` 侧该字段落在**成本节**、label 只叫 "Batch Size"、**无 description 无 `in_list_view`**，从工时视角看不出它是工时基准；③ 工时路径被那个"讲任务单"的开关门控，不勾即退回 `BOM.quantity`。**故"全厂共用同一 BOM 基准量"这个观察对默认路径是对的——错在当成了唯一路径。** |
| **`setup_time` 缺失**（据称故表达不了"20 分换型 + 每支 0.05 分"） | **部分成立，应降为"便利性改造"而非缺口。** 成立的半句：**单行内**固定与线性二选一、不相加（`work_order.py:1548-1551 calculate_time()` 仅一句 `if not d.fixed_time: d.time_in_mins = flt(d.time_in_mins) * flt(self.qty)`），且 `setup_time`/`setup_mins` 全仓**零命中**。<br>**不成立的半句**：Routing **拆成两行**即可原生表达——一行 `fixed_time=1, time_in_mins=20`，一行 `fixed_time=0, time_in_mins=0.05`，用同一 `sequence_id` 并行（该字段 description 明写此用法）。**故 `setup_time` Custom Field 与改 `calculate_time()` 均非必需。** |

**故 LG-055「两者合起来构成工时模型标准化、是 C3/C4 的共同前置」这一判断的前提已变**——工时模型原生基本够用，真正的前置是**换型矩阵**（工序对工序，非单值 `setup_time`）。

**另一项已核实为部分不准**：`Item Variant Attribute.attribute_value` **确是 `Data`（字符串）**故值不可直接参与计算、范围查询是字符串比较（LG-054 原话成立）；**但属性定义层原生有数值能力**——`Item Attribute` 有 `numeric_values`(Check)/`from_range`/`to_range`/`increment`，`item_attribute.py:86-105` 在 `numeric_values` 为真时校验范围与步进。**故"线径 0.5~5.0 步进 0.1"这类约束不必自建**，差的只是"属性代入公式算用料量"。

前两项（展开长度、变体属性）**不在 R1 的 52 场景里**（场景集按业务环节切，这两条是数据粒度的）。排序时须把"前置型"与"并列型"分开看，详见 [S1 概况](S01-场景摸底/P1-S1-概况.md) 的 LG-054・LG-055。
