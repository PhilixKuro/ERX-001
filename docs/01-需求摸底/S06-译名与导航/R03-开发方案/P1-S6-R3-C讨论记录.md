**② 侧栏条目用官方现译名，还是全站改成需求表里的名**

**提出者：** Claude（派只读子 Agent 对合并字典查侧栏各条目的现译与占用时发现）

**背景：** 需求文档 §4.6.2 侧栏表的「条目（中文）」列有 13 项与该单据／报表的现行官方译名不同。侧栏 label 是英文源词、经 `boot.py:465` 的 `_(item.label)` 译出，**csv 一改即全站改**（单据标题、表单、列表、搜索结果同步变）；若只给侧栏另起源词，则会出现「侧栏叫 A、点进去叫 B」。

| 需求表 | 官方现译 | 源词 |
|---|---|---|
| 发货单 | 销售出库 | `Delivery Note` |
| 采购收货 | 采购入库 | `Purchase Receipt` |
| 库存凭证 | 物料移动 | `Stock Entry` |
| 工单 | 生产工单 | `Work Order` |
| 物料申请 | 物料需求 | `Material Request` |
| 库存盘点 | 库存调账 | `Stock Reconciliation` |
| 质量检验 | 质检单 | `Quality Inspection` |
| 报价单 | 报价 | `Quotation` |
| 工位 | 工站 | `Workstation` |
| 总账 | 会计总账 | `General Ledger` |
| 库存台账 | 物料凭证 | `Stock Ledger` |
| 库存余额 | 库存余额(收发存汇总表) | `Stock Balance` |
| 库存与账务价值对比 | 库存与会计账金额对账 | `Stock and Account Value Comparison` |

另：`UOM` 官方译「单位」（需求表写「计量单位」）、`BOM Variance Report` 官方译「BOM差异报表」（需求表有空格）——同属此类，一并按本裁决办。

| 选项 | 描述 | 优点 | 缺点 |
|---|---|---|---|
| 沿用官方名（推荐） | 侧栏 label 直接用单据英文名，显示官方现译；仅明显误导的个别词另行定词（方案列候选） | 零覆盖；侧栏与单据同名 | 需求表那 13 个中文名不出现 |
| 全站改成侧栏名 | 13 条进 csv 覆盖官方译名、进覆盖清单 | 名字更顺 | 演示线外全部渲染点一起变，改动面大 |
| 逐条定 | 逐条列源码用处后用户逐条选 | 最细 | 本轮多一轮往返 |

**用户回答：** 沿用官方名。

**结论：** **DEC-020**：自有侧栏的条目 label 一律用对象自身的英文名（DocType 名／Report 名），显示官方现译，**不为侧栏另起源词、不为侧栏覆盖官方译名**。需求文档 §4.6.2「条目（中文）」列由此失效、以方案为准。**唯一例外**是演示线撞名组按 DEC-002 必须定词的条目（如 `Stock Ledger` 与 `Stock Ledger Entry` 同译「物料凭证」），走演示线档的定词规则，方案列出候选（Part2 §三）。

**③ LG-007：Claude 自定的四个词**

**提出者：** Claude（需求文档 LG-007 要求 C 步交用户过目）

**背景：** 子 Agent 在合并字典上复查四个候选中文，均无源词占用：

| 源词 | 现译 | 候选 |
|---|---|---|
| `Create Chart Of Accounts Based On` | 科目表模板（与 `Chart Of Accounts Template` 同显） | 科目表建立方式 |
| `Disable Opening Balance Calculation` | 无 | 不计算期初余额 |
| CRM `Closed Date` | 截止日期 | 实际成交日期 |
| 自有图标与侧栏显示名（源词拟 `Business Flow`） | 无 | 业务流程 |

**用户回答：** 四个都认可。

**结论：** **DEC-021**：四词照候选落。自有图标 label 与侧栏 title 的英文源词定为 **`Business Flow`**（`Workflow` 已是「工作流」，不用）。LG-007 闭合。

**④ `Dr` → 借方 的称谓侧代价（RS-003／LG-004）**

**提出者：** Claude（需求文档 §4.2.4 要求「落地前先查 `tabSalutation`，若有记录名为 Dr 报用户再定」）

**背景：** 实查（`bench --site … mariadb`）：

| 站点 | `tabSalutation` |
|---|---|
| 演示站 `erx.localhost` | 0 条 |
| 测试站 `test.localhost` | 9 条英文记录，含 `Dr`（英文环境建出） |

读码（子 Agent）：称谓记录由 `frappe/desk/page/setup_wizard/install_fixtures.py:41-55` 按向导语言 `_()` 后插入、以 `salutation` 字段命名，故中文向导建出的记录名本就是「博士」；`Salutation` 为 `translated_doctype`，Link 显示经 `__(value)` 不带 context（`link.js:120-125`、`formatters.js:213`）。故加 `Dr,借方` 只影响「记录名恰为英文 `Dr`」的站——即测试站。erpnext 用作借方缩写的三处：`account_tree.js:63`、`bank_clearance.py:84`、`bank_reconciliation_grid.html:16`，现都显示「博士」。

| 选项 | 描述 |
|---|---|
| 照落（推荐） | 只影响测试站测试数据；D 回执记下代价 |
| 暂不落 | 科目树、银行对账里的「Dr」继续显示「博士」 |

**用户回答：** 照落 `Dr,借方`。

**结论：** **DEC-022**：csv 加 `Dr,借方`，进覆盖清单（依据 DEC-003／022）。已知代价：英文环境建出的称谓 `Dr` 在 Link 中显示「借方」；演示站与中文装站不受影响。RS-003、LG-004 前半闭合；LG-004 后半（全新中文装站是否建出「借方」称谓）按读码不会——记录名在插入时已是「博士」——留 D 步若遇全新装站顺带核。
