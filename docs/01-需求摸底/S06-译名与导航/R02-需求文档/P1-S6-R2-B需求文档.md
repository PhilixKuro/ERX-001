## 二、初始目的

**需求怎么来的**。P1 的定位第一条约束是「不应该出现有些翻译了有些没翻译」——客户看到同一侧栏两个「设置」、科目下拉里两个「应收账款」、以及成片未译英文词，会直接怀疑软件的可靠性（需求图谱 CR-002）。S1 实操时累积了一批「点错地方」的译名缺陷（`PH-P1001`），S3 为演示线定了目标侧术语标准（143 组撞名：73 改／70 不改），S5 装进四个官方 App 后，缺口从 ERPNext 一家扩到六家。与此同时，ERPNext 原有导航按模块分 22 张侧栏，客户跟不上「接单 → 排产 → 领料」的顺序（CR-010），S4 做的结转凭证、小企业三表等又根本没有导航入口、只能靠顶部搜索进（`PH-P1059`）。

**用户的原始表述**（A 步第 6 步，忠实概括）：自定义图标里放演示链路会用到的、以及以后最常用的功能，相当于一个**整理版**；但也要让客户看到 ERPNext 本身能做的远不止这些，所以**不隐藏原生图标**，客户有需要时还能经原生图标找到想要的功能。另（A 步第 9 步）：用户对软件的所有修改都经 AI 进行，故让 AI 在合适的时候**自动运行自检**，甚至当作测试的一部分。

**这个 Stage 为什么排在 S5 之后、S7 之前**：每接入一个 App，译名与导航各多一份工作量，故等四个 App 都进场再做（路线文档 §二 修正 1）；S7 的演示脚本节点名与提示文案要用最终译名写，反序则要改两遍（硬次序①）。

**要解决的核心问题**：

1. **全量无缺口**：合并后缺口 5338 条（A 步第 1 步实测）全部补上，客户点到哪里都不露英文。
2. **演示线上不撞名、不误导**：同一屏或同一侧栏里不出现两个同名标签；会改数据的按钮说的与做的一致。
3. **译名不被静默盖掉**：`Translation` 草稿记录、`frappe_china` 里出现的 `.po`／`.mo`、与法定报表列头同名的中文键，三种情形都会让正式译名失效而不报错——要有自检在演示前拦住。
4. **演示全程不跳侧栏**：一张自有侧栏列全演示对象，原有入口一个不动。

**本 Stage 不做的**（边界）：演示后精确档（DF-002，S8G-S4）；演示线外的撞名（属 DF-002，DEC-002）；单号格式（`PH-P1014`，等实地考察）；拼音检索（`PH-P1007`，RL-06）；隐藏或折叠任何原有入口（DEC-005）；演示用户与权限（S7）；`after_migrate` 挂点（S8G-S1 的 IM-007）；账结法下可用的试算表（`SH-P1S6001`）；改各 App 自己的 `.po`（ADR-0006）；改 erpnext 原有侧栏与图标记录（ADR-0011）。

## 七、预期使用流程

**实施者（D 步）**

1. 重跑基线脚本，得缺口与撞名清单。
2. 写自检与测试改造，先让反证用例能报失败。
3. 演示线档：按清单逐条定词写 csv；落 §4.2.4 点名用词；查 `tabSalutation` 后落 `Dr`。
4. 批量档：批量译、分层抽 100 条、按 DEC-017 判定。
5. 裸渲染点三条出路各实测、可行的落地。
6. 底稿改名与补丁；S4 小缺陷四处；开账凭证跳转。
7. 按钮抽检表。
8. 自有图标、svg 与侧栏；测试站点检树形 DocType；`PH-P1002` 逐例复现。
9. 演示站 `bench migrate`、`bench build`、清缓存；跑自检；按屏清单逐屏截图核；出新的空账基准点备份。
10. 写开发守则「何时跑自检」条目。

**演示者（演示当天）**

1. 首页点最前面的「业务流程」图标。
2. 按自有侧栏从上往下：基础资料 → 销售（`/crm` 线索、商机、数据面板，再回 desk 接单）→ 采购 → 库存 → 生产 → 财务 → 报表，全程侧栏不变。

**AI（之后每次改动）**

1. 改过 csv、在演示站界面上改过配置、涉及译名的提交前、演示前——跑自检（测试站随测试套件、演示站单独跑一次）。

## 九、术语定义

| 术语 | 定义 |
|---|---|
| 缺口 | 按 §4.2.1 口径，六个 app 的源词中在合并后字典里没有中文的条目 |
| 合并字典 | 按 `installed_apps` 顺序叠加七个 app 译名（含 csv）后的结果，后者覆盖前者 |
| 撞名组 | 合并字典里同一中文对应两个以上源词的一组 |
| 占用 | 某中文词已是某源词的译名；改词前须查新词未被不同义的源词占用 |
| 演示线面 | §4.2.2 四部分的并集；逐条看源码定词的范围 |
| 演示线档／批量档 | DEC-001 的两档质量：前者逐条结合源码译，后者批量译后抽检 |
| 可用 | §4.2.3 三条判据全满足 |
| 覆盖清单 | 测试侧登记的、csv 中覆盖了官方译名的全部键及其依据 |
| 裸渲染点 | 调 `__()` 时不传 context、只能吃无 context 那一行译名的渲染位置 |
| context 行 | csv 三列行，只在渲染点传了同名 context 时生效 |
| 自有图标／自有侧栏 | §4.6 的「业务流程」首页图标与其侧栏，`app=frappe_china` |
| 整理版 | 自有侧栏的定位：演示链路＋以后最常用，原有入口全部保留（DEC-004） |
| 屏清单 | §4.9 两张表，完成标志①的验收对象 |
| 演示站／测试站 | `erx.localhost`／`test.localhost`（见 S5 需求文档 §九） |
| 反证 | 故意制造失败条件，确认检查会报失败 |
