# ADR-0014: 演示编排——配置驱动 + 快照进度

- 状态：accepted
- 日期：2026-10-20（落成）／决策出自 P1-S8-R3 A 步第 4～8、18～19 步与 P1-S8-R2 第 54～55 步
- 决策者：用户裁决，Claude 提选项
- 对应决策：P1-S8 DEC-005～009、DEC-011、DEC-031～034、DEC-038；R2 DEC-014
- **部分取代** [ADR-0008](ADR-0008-演示操控的事件协议.md) 的「无状态」与备选方案中「小 DSL」的否决（NV-039）；ADR-0008 的协议本体（事件名、payload、`seq`、`user` 必传）不变

## 上下文

ADR-0008 设想的演示是「半自动、无状态」：脚本推一个事件，界面跳到 23 个节点之一并填好，「走到第几步」握在演示者手里；节点函数硬编码，因为当时判断 23 个节点形态不同构、通用解释器（小 DSL）做不好。

P1-S8 改变了三个前提：

1. **演示形态变了**：用户要「时间快进」式演示——现场演一段，再把场景时间推进几个月接着演。快进靠切换到预先存好的数据快照，系统必须知道下一份快照是哪份，故须有状态。
2. **R2 人工实操后，用户选了配置驱动**（R2 DEC-014）：配置文件管顺序、参数、讲解词、停顿，多数步骤用通用动作，复杂步骤挂命名函数——即 NV-039 否决过的方向，加上命名函数作逃生口。
3. **推进不再经服务端推事件**：用户先要同屏快捷键（DEC-009），浏览器自身推进，演示时用不到 realtime 推送。

## 决策

**演示由 `frappe_debug` 内的一份演示配置驱动，进度写在数据库快照里。**

| 部分 | 决定 |
|---|---|
| 配置 | 演示配置（幕、步、讲解词、停顿、快照点）＋场景参数文件（场景数据）两份；通用动作＋命名函数；加载时整份校验，未知动作或引用开播前即报错 |
| 推进 | 同屏快捷键，讲解词浮窗可隐藏；手机遥控延迟（`SH-P1S8003`，届时复用 ADR-0008 协议） |
| 进度 | 「演示进度」DocType，每份快照里一条；恢复哪份快照即读到哪份的进度 |
| 快照 | 每幕开头一份：原始快照＋预导好的主用库、备用库；快进、重来、跳幕＝改站点 `db_name` 指向目标库，清站点配置缓存，删 redis 目标库前缀键，把当前会话行抄进目标库 |
| 预跑 | 真实浏览器以彩排模式把整场播一遍、幕首自动存快照；幕间快进数据由生成器在服务端造 |
| 驱动 | desk 走 `cur_frm` 等前端 API；`/crm` 走弹窗界面驱动＋读回＋接口兜底。均为页内脚本，不另写 Cypress／Playwright 驱动 |
| 场景日期 | 场景终点＝预跑当天；现场单据由框架统一带本幕场景日期 |

**约束**：演示站 web 为单进程 `bench serve`；换库前页面离开 desk；快照库对站点数据库用户授权；RQ worker 跨换库的行为须在实现快进前验掉（S8 LG-002）。

## 后果

**正面**
- 进度与数据恒一致：状态就在数据里，回应了 NV-041「有状态即可失同步」的否决理由；「从任一节点起跑」变为「换到该幕快照」，不需 reset 接口。
- 快进 3～5 秒（V-01② 26／26），不碰 `bench migrate`（无变更也要约 10 分钟）。
- 彩排即完整检查：现场与预跑同一套代码同一条路径。
- 调演示顺序、讲解词、停顿只改配置。

**负面**
- 每幕两份库加原始快照，磁盘约 2 GB。
- 预跑要开着浏览器窗口，按 1～2 小时估；预跑后改了代码须重跑。
- 换库只在单进程 web 下验过；多 worker 部署不支持。
- 改 `db_name` 与抄会话行是高权限操作，只许 Administrator 调，且只存在于客户库不装的 `frappe_debug`。

**中性**
- ADR-0013 里 `frappe_debug` 内部「`nodes/` 23 个节点的业务定义」与「`drivers/desk`（Cypress）／`drivers/spa`（Playwright）」的分层，演示部分改读为「演示配置＋通用动作＋命名函数」与「页内驱动脚本」。`data/`（建单辅助，生成器与命名函数共用）不变，ADR-0010「共用建单辅助函数、不共用节点定义」不变。
- `frappe_china` 的推送助手与事件协议留给 S8 之后的遥控与心跳自检。

## 备选方案

**控制端记进度**（演示控制台按配置顺序记当前第几步）—— 简单。**没选**：控制台刷新或重开即丢；记的进度可能与库内数据不符。

**服务端代做预跑**（通用动作在服务端再实现一遍）—— 最快、不用浏览器。**没选**：一动作两套实现，界面那套出错时预跑发现不了。

**无界面浏览器代跑预跑**—— 无人值守。**没选**：容器内要装浏览器环境，desk 与 `/crm` 两套界面都要驱动。

**快进走 `bench restore`＋`bench migrate`**—— 备份文件不变、重来天然干净。**没选**：实测 632 秒（V-01①）。见 S8 NV-001。

**换库后自动登录**—— 两种恢复路径都实测过。**没选**：要在 `frappe_debug` 里存演示密码；抄会话行更快（V-03）。

## 失效条件

- 演示须用多 worker 部署，或 RQ worker 换库后写错库且无法规避时（DEC-031）。
- 演示机磁盘放不下约 2 GB 的快照时（DEC-032）。
- 预跑须无人值守、不能开浏览器窗口时（DEC-008）。
- 通用动作覆盖不了主路径、命名函数占多数时（R2 DEC-014）。
