4. **CR-012 必须走单据、不能裸插数据**：直接写库、或 insert 时带 `docstatus:1` 会跳过 `on_submit` ⇒ **GL Entry 与 SLE 不生成、财务与库存不一致，AI 分析出来的结论是错的**。
5. **CR-012 的口径是全链**（用户第 25 步明示）：从销售漏斗到生产到交付货物全流程。三项数据要求：多个 BOM（据公开资料）／数十个供应商与客户／**最好带历史成交单价**（`Item Price` 原生支持 `supplier`/`customer`/`valid_from`）。
6. **样本产品范围**：**压簧 + 拉簧**两类，均取自国标参数表、可溯源；**扭簧无国标尺寸参数表，不编造数值**。命名用**国标型号标记法**（如 `YA 1.2×8×40 GB/T 2089`），故 DF-001 参数字段零开发即可满足演示。
7. **CR-011 是 A/B 两套**（DEC-028 兜底形态）：A 套从零演示、B 套已推进到各节点。**A 套第 N 步卡住即切 B 套那条“已过第 N 步”的单据往下走。**
8. **⚠ 报工工时必须填合理值**（图谱落地纪律 1）：任务单计时几秒即导致工序成本记 0.27 元而非应有的 433.3 元、**毛利率虚高 40 个百分点**。这靠培训与流程约束解决、代码改不了，**但样本数据的工时必须合理**——客户看到漂亮但错误的成本数字，比不演示更糟。
9. **CR-008 的事件协议已定稿**（ADR-0008，契约全文在 P1 概况）：单一事件名 `erx_demo_step`／payload `{node, params?, seq}`／**`seq` 必需**（`realtime.py:74-84` 的 `after_commit` 队列按 `(event, message, room)` 整体去重 ⇒ 同一节点重推会被静默吞掉）／**`user` 必传**（不传则落 `get_site_room()` = `"all"`、广播全站）／**无状态**（走到第几步握在演示者手里）／**未知节点名必须响亮失败**。

20. **一年期场景的形态**（v1.11，P1-S7-R1 第 2 步⑤，S7 DEC-007／010）：要一个可信的长时间段场景（如一整年），尽量覆盖各环节的各种可能。主线是：先正常找订单、接订单、**按订单进料**、生产、销售；然后加**经济订货批量**入料，同时接单生产销售继续发生；再加**覆盖 N 天用量**入料。三种补货规则按阶段依次启用，让客户看到策略切换前后库存与资金占用的变化。**CR-004 损耗反算、IM-018 按毛利选 BOM 与 IM-010～IM-017 都要在这一年里有对应单据并进演示**（v1.12：IM-014 已延迟，不含换型，S7 DEC-015）；质检读数、报工工时、多 BOM 按真实分布造，不能是几条样例。
21. **一年期场景的四条数据约束**（v1.11，按 ERPNext 机制推断、未实测，S7 LG-002）：① 一年须是**过去**的一年（如 2025-10～2026-09），生成器按日期回填，演示当天从「今天」接着实时推——系统不允许把库存单据记到未来日期；② 补货 daily 只看当下库存、不补跑过去，生成器须**逐日推进模拟日期**、调 S7 补货计算的「按某日计算」入口；③ 回填过去日期的库存单据会触发库存成本重算排队，须**严格按日期先后生成**、不乱序补单；④ 账结法要做 **12 次月末结转**，生成器按月调 S4 的结转。
22. **原第 5 条「三项数据要求」与第 15 条「三问口径」照旧适用**，但「100 条」口径作废；数据集变了，三问各 3 次的实测（`SH-P1S5006`）须按一年期数据重测。
