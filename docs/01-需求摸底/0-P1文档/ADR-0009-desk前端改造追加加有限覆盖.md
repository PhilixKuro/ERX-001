# ADR-0009: desk 前端改造——追加 + 有限覆盖，每处登记

- 状态：accepted
- 日期：2026-09-25 / 决策者：用户裁决（C 步第 14 步①），Claude 提选项
- 对应决策：DEC-060

## 上下文

多条需求要改 desk 自带前端的行为：LG-074 的 `/undefined` 404、EN-001 的树视图、CR-008 的节点函数注入、CR-010 的导航噪音折叠。desk 前端没有正式扩展点，`app_include_js` 注入的脚本只能在已定义的类与方法上打补丁。

V-16 探针已证四种手法可覆盖且 `bench build` 后仍生效。**但它只证了「能覆盖」、未证「能撑多久」**——这些补丁押在上游非公开 API 上，上游改个方法名即静默失效。

## 决策

**追加为主，覆盖为辅，每处覆盖登记进一张表。** 能用追加（新增而不改已有行为）达成的一律追加；确需改已有行为的允许覆盖，但每一处必须登记：覆盖了哪个类的哪个方法、依赖上游哪个版本的什么行为、失效时的症状是什么。

## 后果

**正面**
- LG-074 与 EN-001 都能修，不必绕道。
- 登记表是升级后唯一的复验依据——上游一改，照表逐条复验即可，不必凭记忆找。

**负面**
- 每处覆盖都是技术债，且债务的到期日不由我们定（上游升级时到期）。
- 登记表要人维护，漏登一处就等于那处的失效不可预警。

**中性**
- 与 `开发守则.md`「扩展优先用 hook 不改源码」的精神一致（我们不改 erpnext 源码，只在自有 app 里打补丁），但精神的边界在此被用尽——再往前一步就是改源码。
- **⚠ 注入脚本内须明确分区，两类补丁的时机相反**：realtime 监听须在 `$(document).on("app_ready", ...)` 内注册（`socketio_client.js:12-17` 的 `on()` 在 `this.socket` 不存在时**静默不做任何事**，socket 由 `desk.js:34` 的 `init()` 创建）；而 V-16 已证类原型补丁可在 parse 阶段直接打。同一份文件里两种时机并存，不分区必错。

## 备选方案

**只做追加、不做覆盖** —— 完全不依赖上游非公开 API，升级零风险。**没选**：LG-074（`/undefined` 404）与 EN-001（树视图）都修不了。**未采但保留为退路**——若覆盖在升级后反复失效，可退到此。见 NV-046。

**放开覆盖、不设限** —— 开发时最快，不必为每处写登记。**没选**：升级时无处可查改了哪些；与 `开发守则.md`「扩展优先用 hook 不改源码」的精神相悖。见 NV-047。

- 被依赖：ADR-0008（节点函数经本机制注入）、ADR-0011（导航重整的开发期手段）
- 取代：无

## 失效条件

若上游提供正式的前端扩展点。
