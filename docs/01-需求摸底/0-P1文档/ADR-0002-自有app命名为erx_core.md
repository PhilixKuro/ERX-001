# ADR-0002: 自有 app 命名为 `erx_core`

- 状态：accepted
- 日期：2026-09-25 / 决策者：**用户第 17 步补裁**，Claude 提议
- 对应决策：DEC-053

## 上下文

ADR-0001 定下单 app 后需要给它一个名字。**这是全部 12 条架构决策里最不可逆的一条**——app 名一旦 `bench install-app` 装进站点，就成了 `installed_apps` 全局值里的字符串，改名要 `uninstall-app` + 重装，或手改全局值绕过 installer。

**⚠ 本条决策有一段越权史，须随记录保留。** C 步第 2 步②的原记录写成「定案——单 app，名 `erx_core`」，而用户当时只答了选项字母 A（单 app）；`erx_core` 是 Claude 的偏好，其原文自己写着「**这是可改的偏好、不是判断**」。此后十余步一路按 `erx_core` 书写属越权，第 16 步③机械核实（两份 transcript 全部 19 条真实用户发言里 `erx_core` 零命中）查出，**用户第 17 步补裁采纳**。

**⭐ 越权的代价与该项的不可逆性成正比，而记录恰恰在第 2 步就标注过它最不可逆。** 若用户当时否掉这个名字，要改的地方包括 ADR-0003／0006／0008／0012 的结论、模块目录结构、前瞻性设计 P-3、架构图两层、GAP-002、LG-101。

## 决策

自有 app 名为 **`erx_core`**。`erx` 承项目代号，`core` 留出将来真要拆 app 时的命名空间。

## 后果

**正面**
- 与项目代号 ERX-001 呼应，一眼可辨是自有代码。
- `core` 后缀为将来拆分预留命名空间（`erx_demo`、`erx_mfg`），拆分时不必给现有 app 改名。

**负面**
- **装进站点后即冻结**。改名的成本不只是重装，还包括上列一整批引用位置。

**中性**
- `core` 这个词在当前形态下没有对应物（app 内部并不存在「非 core」的部分），它是为未来留的名字而非对当下的描述。

## 备选方案

本条是补裁项，无独立选项表。C 步第 2 步②里 Claude 只提出过 `erx_core` 一个候选并同时询问用户「或你另有偏好」，用户当时未答、第 17 步采纳该候选。**故本条没有被否决的备选方案**——这一点如实记录，不虚构选项。

## 关联

- 被依赖：ADR-0003、ADR-0006、ADR-0008、ADR-0012（全部以 `erx_core` 为书写前提）
- 取代：无

## 失效条件

装进站点后即冻结。
