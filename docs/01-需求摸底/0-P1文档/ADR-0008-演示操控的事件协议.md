# ADR-0008: 演示操控的事件协议——单一事件名 + 无状态

- 状态：accepted
- 日期：2026-09-25 / 决策者：用户裁决（C 步第 11 步①），Claude 提选项
- 对应决策：DEC-059

## 上下文

CR-008 要求演示可被半自动操控：演示者触发一步，界面自动完成该步的填单／点击动作，演示者讲解，再触发下一步。23 个业务环节各是一个节点。

机制侧：Frappe 的 realtime 走 socketio。服务端 `publish_realtime()` 推事件，desk 前端 `frappe.realtime.on()` 收。

**本决策是本轮唯一要升进本 Phase 概况当跨单位接口契约的一条**——契约面越小，远期 React 重写时要兑现的越少。

## 决策

**单一事件名 `erx_demo_step` + payload `{node, params?, seq}` + 前端按 `node` 查表分派到节点函数 + 服务端与前端均无状态。**

- `seq` 递增必需：`realtime.py:74-84` 的 `after_commit` 队列按 `(event, message, room)` 整体去重，连推两次同一节点时若无 `seq` 则第二次被吞。
- 推送侧 `publish_realtime(event, message, user=演示用户, after_commit=True)`，**`user` 必传**——否则 `realtime.py:58-72` 落到 `get_site_room()` = `"all"`，广播给全站 desk 用户。
- 节点清单两侧各存一份；未知节点名必须响亮失败（`console.error` + `frappe.msgprint`），不得静默。

## 后果

**正面**
- 契约面最小：一个事件名 + 一个 payload 形状 + 一份节点清单。
- 「从任一节点起跑」天然成立——推 `{node: X}` 即可，不需要 reset 接口。
- 无状态则不会与演示者的手动操作失同步（半自动语义下「走到第几步」本就握在演示者手里）。

**负面**
- 节点清单两侧各存一份，加节点要改两处。这是无状态与最小契约面的代价。
- 节点函数是硬编码的，23 个节点各写一个函数，没有复用通用解释器带来的行数节省。

**中性**
- **⚠ 共享面的确切边界：只共享推送侧与事件名／payload 形状，不共享连接建立方式。** desk 侧连接走 boot 负载 + `RealTimeClient`（`boot.py:166`）；独立前端走 `window.socketio_port`（由 `templates/base.html:53` 注入）+ 自己 `io()`（样本 `frappe-crm/frontend/src/socket.js`）。需求图谱 §7.3 已把这一行明写为「**不共享**」。本条按 C 步复核建议第三节第 3 条的建议，把「不共享什么」显式写进契约。

**一条随本协议生效的硬纪律：CR-009 的心跳自检必须真做一次事件往返，不能只查「socket 连上了」。** 依据 `frappe.boot.disable_async` 为真时 `init()` 置 `disabled=true` 直接 return ⇒ **socket 根本不被创建**，此时「查连接状态」这个动作本身无从执行、查不出任何东西。故自检的形态必须是「服务端推一个自检事件、前端收到后回显」，一个真往返。**这条与「未知节点名必须响亮失败」是同一件事的两端**：前者保证通道本身可验，后者保证通道通但节点名错时不被误读成通道断——而这两种症状在界面上完全相同，正是 CR-009 要消除的混淆。

## 备选方案

**单一事件名 + 服务端数据定义节点 + 前端通用解释器（小 DSL）** —— 加节点只改数据不改代码。**没选**：**23 节点的操作形态不同构**（填子表／点按钮／选下拉／等异步），DSL 要么加特例要么表达不了，最后成半通用半硬编码；且违反 CR-008「只做到够演示用一档」的范围约束。见 NV-039。

**每节点一个事件名（23 个）** —— 前端各自注册，互不干扰。**没选**：**契约面 23 倍**——23 个名字全成为跨 Phase 契约，23 次 `on()` 注册，加节点要同时改两侧；**而它声称的「可从任一节点起跑」在单一事件名下同样成立**（推 `{node: X}` 即可），不是独有优点。见 NV-040。

**带状态机**（服务端记当前步／前端记）—— 可做「下一步」按钮而不必指定节点。**没选**：半自动语义下「走到第几步」本就握在演示者手里，系统不必记；有状态即可失同步（人若手动点了别处），且「从任一节点起跑」要另加 reset 接口；前端记还刷新即丢。见 NV-041。
