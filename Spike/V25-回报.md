# V-25 回报 — 双栏资产负债表跨两个会计年度时的列头实际长相

**命题**（收窄后）：双栏模板 ＋ 两个会计年度时，**列头由引擎的期间轴生成，模板层无法把它控制成逐字「年初余额／期末余额」**。

**判定**：**`go`**（缺口成立）—— 但 **R1 记载的判据「列头是年份（`2025`/`2026`）」不准确**，实际形态是 `段标签 - 期间标签`，且**段标签那一半由模板控制**。

**探针**：`V25-column-headers.py` ／ 原始输出 `V25-out/column-headers.json`
**站点**：`erx.localhost`，公司 `华东弹簧`（唯一一家）
**写入**：无。会计年度 2025 在事务内建出、`finally` 里 `rollback()`，全程无 `commit()`。已验回滚干净（`fiscal_years_after_rollback` = `["2026"]`）

---

## 一、实测到的列头

拿出厂模板 `Horizontal Balance Sheet (Columnar)`（64 行、3 个 `Column Break`、2 个 `Section Break`）跑真引擎，`filter_based_on=Fiscal Year`、`from=2025`／`to=2026`、`periodicity=Yearly`：

| fieldname | label |
|---|---|
| `seg_0_account` | **`Equity & Liabilities`** |
| `seg_0_dec_2025` | **`Equity & Liabilities - 2025`** |
| `seg_0_dec_2026` | **`Equity & Liabilities - 2026`** |
| `seg_1_account` | **`Assets`** |
| `seg_1_dec_2025` | **`Assets - 2025`** |
| `seg_1_dec_2026` | **`Assets - 2026`** |

行数 34，数字拿得到（`seg_0_dec_2025` / `seg_0_dec_2026` 有实值）。

**⇒ 列头不是裸年份**，是 **`段标签 - 期间标签`** 两段拼接。

## 二、两段各由谁决定

**段标签来自模板。** 判据 `financial_report_engine.py:1727-1728`（`MultiSegmentFormatter.get_columns`）：

```python
if segment.label and col["fieldname"] in [p["key"] for p in self.period_list]:
    new_col["label"] = f"{segment.label} - {col['label']}"
```

而 `segment.label` 取自 `Column Break` 行的 `display_name`（`:1712` 一带 `segment_label = getattr(row_data.row, "display_name", "")`）。**出厂模板那两个 `Column Break` 的 `display_name` 正是 `Equity & Liabilities` 与 `Assets`**，与实测列头逐字吻合。

**期间标签来自引擎，模板层无入口。** `financial_statements.py` 内全部 label 赋值点只有 7 处，全部由 `periodicity` ＋ 日期算出（`formatdate(..., "YYYY")` 等），无一处读模板。且：

- `Financial Report Row` 的 21 个字段：`reference_code`／`display_name`／`indentation_level`／`data_source`／`balance_type`／`fieldtype`／`color`／`bold_text`／… —— **无任何 `label` 或 `header` 字段**
- `Financial Report Template` 的 7 个字段：`template_name`／`report_type`／`module`／`disabled`／`rows`／两个 break —— **同样没有**

**⇒ 「年初余额／期末余额」这种逐字列头做不到**：段标签能写成中文，但引擎必然在其后追加 ` - {期间}`。要得到逐字合规的两列，只能自己接管列轴。

## 三、`Custom API` 管不了列头

`:1185` 的契约是：

```python
values = frappe.call(method, filters=self.context.filters, periods=self.period_list, row=row)
```

返回值绑给 `values` —— **一个按期间排的扁平数值列表**。故 `Custom API` 是**行级取数出口**，改不了列的数量与名字。R1 讨论记录第 7 步议题 ⑤ 把它当成「解决列头合规问题的那个出口」，**这一点不成立**。

## 四、⚠ 一处必须声明的探针自身产物，不是产品缺陷

纯函数段我用 `ignore_fiscal_year=True` 调 `get_period_list`，`accumulated_values=True` 时标签跑出 **`-2025`／`-Jan 25`**（前导横线）。成因是该参数跳过 `from_date_fiscal_year_start_date` 赋值，`formatdate(None)` 得空串，于是 `"" + "-" + "2025"`。

**真实报表路径不走这条**：`_initialize_context():279-288` 调 `get_period_list` 时**根本没传 `accumulated_values`**（取默认 `False`），故走的是 `label = get_label(periodicity, from_date, to_date)`，实测输出干净的 `2025`／`2026`。

**这条横线是我造的，不要当成产品 bug。** 附带得到一条真事实：**FRT 路径下 `get_period_list` 的累计标签分支是死代码。**

## 五、复核建议

1. **最该先看的：本条判定的「缺口成立」是结论对、判据换了。** 若 B 步照抄 R1 原文「列头是年份」，会在需求文档里留下一个可被下一个人证伪的判据。查法：读 `V25-out/column-headers.json` 的 `engine_columns_two_FY_yearly` 键，六个 label 逐字对照；再读 `row_doctype_fields` 与 `any_column_label_field` 两键确认模板层无列名字段。
2. **观察范围**：`erx.localhost` 单站点、单公司、出厂模板、`Yearly` 与 `Monthly` 各一次。**未验**自建模板给 `Column Break` 填中文 `display_name` 后列头长什么样 —— 按 `:1727` 的代码它应是 `中文 - 2025`，但我没实跑。这条若要作准，值得补一次。
3. **拿不准处**：命题被我从「列头的实际长相」（不可判真假）收窄成「能否逐字合规」。**收窄后仍回答得了原问题**——原问题要的就是「这个判据站不站得住」。但收窄丢掉了一件事：**列头合规到什么程度才算合规**，那是判断题不是事实题，R1 复核建议第 1 条已点出它取决于给谁看（内部管理／报送税务／会计师审阅），不在本探针射程内。
