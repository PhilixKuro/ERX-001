# V-05 探针：专票/金税盘对接的现实可得性

命题：主流服务商（航信/百望/诺诺等）的开票接口是否需要企业资质或商务签约才能申请到测试环境
—— 即本项目现阶段能否自行完成技术验证。

## 手段与边界

本条不靠读源码，靠查服务商开放平台与实测网络可达性。**本探针未使用任何第三方凭据发起
业务调用**：社区流传的沙箱 appKey/appSecret 不属本项目，用它签名开票请求属于以他人凭据
访问第三方系统，探针主动放弃该步（工具侧亦拒绝执行）。故下列结论中"沙箱是否接受业务请求"
一项**只到协议层与错误码层，未做成功开票**。

## 实测记录（2026-09-22，经本机代理 127.0.0.1:7897）

### 1. 诺诺（航信系）沙箱端点可达

```
$ curl -o /dev/null -w "HTTP=%{http_code} time=%{time_total}s" \
    https://sandbox.nuonuocs.cn/open/v1/services
HTTP=200 time=0.321687s

$ curl -X POST https://sandbox.nuonuocs.cn/open/v1/services \
    -H "Content-Type: application/json" -d '{}'
{"code":"070501", "describe":"请求的API不存在"}
[HTTP=200]
```

要点：
- 沙箱主机对**未签约、未认证的任意调用方**开放，无网络层或接入层拦截。
- 空 POST 得到的是**业务错误码** `070501`（"请求的API不存在"），不是 401/403/
  "未开通"/"请联系商务"。说明请求已进入其业务路由，平台未在入口处校验调用方资质。

### 2. 开放平台注册入口

```
$ curl -o /dev/null -w "HTTP=%{http_code}" https://open.nuonuo.com/
HTTP=302
$ curl https://open.nuonuo.com/   # 与 https://nuonuo.com/open/ 同
诺诺开放平台-电子发票API接口... You need to enable JavaScript to run this app.
$ curl https://pop3.baiwang.com/
百望云-开放平台
```

诺诺与百望的开放平台首页均为前端渲染的 SPA，curl 取不到注册表单字段，**未能从官方页面
直接读到"注册需要哪些资质字段"**。这是本条最大的未闭合处。

### 3. 文档侧证据（社区来源，非官方页面）

多个独立来源（cnblogs 对接实录、Gitee `nn-sdk` README、CSDN 系列文章）在沙箱环境上
互相一致：

- 沙箱地址 `https://sandbox.nuonuocs.cn/open/v1/services`，
  生产 `https://sdk.nuonuo.com/open/v1/services`。
- 沙箱使用**公开流传的共享测试凭据**（多篇文章给出同一组 appKey/appSecret），
  不是各自申请所得。
- 沙箱配套**测试税号** `339901999999142`；换 `339902999999789114` 可测纸票作废。
- 沙箱下 `token`（access_token）**可为空**——即不走针对真实纳税人账户的 OAuth 授权流程。
  这是沙箱不需要企业实名的技术原因。
- 沙箱支持专票与全电发票红冲测试。

生产侧则一致指向：appKey/appSecret 来自在开放平台注册的自有应用，调用需真实
`salerTaxNum` 并通过授权取得 token，被授权企业须已在平台开通开票能力。
**企业实名与开票资质落在生产侧，不在沙箱侧。**

## 结论

- **沙箱/测试环境：不需要企业资质即可做技术验证**。端点对任意调用方开放（实测），
  凭据为社区共享而非申请制，token 可空（文档一致）。本项目现阶段可自行完成
  报文结构、签名算法、字段映射、红冲流程的技术验证。
- **生产开票：必须有企业资质**。真实税号 + 平台侧开通开票能力 + 授权换 token，
  这三步绕不开，且与金税盘/税控设备绑定。
- 故命题按"测试环境"问 → 不需要资质；按"真开出一张专票"问 → 需要。

## 未触及

1. **未成功跑通一次沙箱开票**——未用他人凭据签名调用（见上"手段与边界"）。
   签名算法、必填字段、返回报文结构均**未实测**，仅有文档描述。
2. **未读到官方注册流程页**——诺诺/百望开放平台为 SPA，未能确认自助注册要填哪些字段、
   是否卡在企业认证步。若要闭合，需在真实浏览器里走一遍注册。
3. **百望云、航信直连未单独验**——只验了诺诺沙箱端点。百望是否同样有开放沙箱未测。
4. **金税盘/税控设备本身未涉及**——全电发票时代多数场景走服务商 API，
   但若客户仍用税控盘/开票软件，那是另一条路径（本地设备对接），本探针完全未触及。
5. 沙箱与生产的**字段差异、限额、并发限制**未查。
