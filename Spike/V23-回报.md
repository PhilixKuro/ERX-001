   没有发票/金税接口。README「功能介绍」自述 6 项，全是 CRM/HR/区划/登录/汉化/按钮权限。
   这与既有结论（saoxia 无 tax localization）一致，本次是正面复核。

   `FRAPPE_BRANCH=version-15` / `ERPNEXT_BRANCH=version-15`；README 称「V15 已通过兼容测试，

## 三、结论

saoxia 与 zelin 在这一点上**同样缺失**：两者都不做月末结转。
zelin 提供科目（`2221007 进项税额转出` / `2221003 转出未交增值税` / `2221020 未交增值税`）
但无凭证逻辑；saoxia 连科目都没有，且完全不进会计域。
**增值税期末结转在两份参考料中均无实现可借，须自建。**

## 四、复核建议

- **最弱处**：判定建立在「静态源码 + git 全历史」上，未装 app 实跑。若该 app 存在
  运行期从外部拉取会计配置的行为（如安装后从某 URL 下载科目表），静态扫描看不见。
  但已查过 `after_install` 全链、`patches.txt`（空）、`scheduler_events`（4 条全企微），
  三处注入点均无网络拉取会计数据的痕迹，故此风险很低。**按 HARD CONSTRAINT 未跑其安装器。**
- **未覆盖**：`erpnext_china/public/js/`、`erpnext_china/templates/pages/` 两目录未逐文件通读
  （已被全库 grep 的 52 个关键词覆盖，A/B/C 组在其中零命中）。
  `old_system_data.py` 按隐私约束只看结构未读内容 —— 但它是纯数据列表，不含逻辑。
- **一处不确定**：`zh.csv:7838-7841` 出现的 `22210101 进项税额` / `22210102 销项税额`
  是**八位**科目号，与 zelin 的**七位**（`2221001`）编码位数不同。这说明 saoxia 作者
  见过某份中国科目表（可能是其自有站点数据，未进仓库），但仓库内确实没有该表。
  若下游要考据「哪份科目表用八位编码」，这两行是唯一线索，但它不构成实现。
