# V-29 回报 — 自建双栏资产负债表、`Column Break` 填中文，跨两年 `Yearly` 的六个列头实测

**命题**：自建一个两段（两个 `Column Break`）的资产负债表 `Financial Report Template`，两个 `Column Break` 行的 `display_name` 填**中文**，用 `periodicity=Yearly` 跨两个会计年度跑，观察实际的六个列头 —— 它们是不是 `中文 - 2025` ／ `中文 - 2026` 的形态？

**判定**：**`go`** —— 是。六个列头逐字就是 `中文` ／ `中文 - 2025` ／ `中文 - 2026`，分隔符是**空格-连字符-空格**（`U+0020 U+002D U+0020`），无任何前后空白。V-25 复核建议第 2 条留的那个未验缺口，本次实跑补上了。

**探针**：`Spike/V29-cn-column-headers.py` ／ 原始输出 `Spike/V29-out/cn-column-headers.json`
**站点**：`erx.localhost`，公司 `华东弹簧`
**写入**：无。会计年度 2025 与三个临时模板全在事务内建出、`finally` 里 `rollback()`，全程无 `commit()`

---

## 一、实测到的六个列头（逐字）

自建模板 `ZZ-PROBE-V29-BS-StatutoryLiteral`，两个 `Column Break` 的 `display_name` 直接填**法定字样** `年初余额` ／ `期末余额`（有意选这两个词：若引擎什么都不追加，光靠这两个名字就合规了）。`filter_based_on=Fiscal Year`、`from=2025`／`to=2026`、`periodicity=Yearly`：

| fieldname | label（逐字） | 码位 | 前导/尾随空白 |
|---|---|---|---|
| `seg_0_account` | `年初余额` | `U+5E74 U+521D U+4F59 U+989D` | 无 |
| `seg_0_dec_2025` | `年初余额 - 2025` | `…U+989D` **`U+0020 U+002D U+0020`** `U+0032 U+0030 U+0032 U+0035` | 无 |
| `seg_0_dec_2026` | `年初余额 - 2026` | 同上，末位 `U+0036` | 无 |
| `seg_1_account` | `期末余额` | `U+671F U+672B U+4F59 U+989D` | 无 |
| `seg_1_dec_2025` | `期末余额 - 2025` | `…U+989D` **`U+0020 U+002D U+0020`** `…2025` | 无 |
| `seg_1_dec_2026` | `期末余额 - 2026` | 同上，末位 `U+0036` | 无 |

**分隔符就是 ` - `（空格＋ASCII 连字符 `U+002D` ＋空格）**，不是裸 `-`，不是全角横线，不是 `U+00A0`。`HYPOTHESIS_CHECK_A_statutory_literal` 键里六列 `exact_match` 全 `true`，`all_exact: true`。

引擎共返 12 列，上表 6 列是 `hidden=0` 的可见列；另 6 列（`seg_N_acc_name` ／ `acc_number` ／ `currency`）`hidden=1`，label 仍是英文 `Account Name` ／ `Account Number` ／ `Currency`，**中文没有传到隐藏列**。

**数字是真的**，列头不属于死列：`seg_0_dec_2026` 有实值 `719.5`（资产合计）。2025 全 0 —— 该公司 GL 只落在 2026-09，这与 V-26 的账实情况一致。

`all_exact: true`。**⇒ 这不是特定字串的偶然**，中文长度（2 字／4 字／8 字）都一样。

### 第三个模板：把 `display_name` 留空会怎样

`ZZ-PROBE-V29-BS-EmptySegmentLabel`，两个 `Column Break` 的 `display_name` 留空：

| fieldname | label |
|---|---|
| `seg_0_account` | `Account (Segment 1)` |
| `seg_0_dec_2025` | `2025` |
| `seg_0_dec_2026` | `2026` |

## 二、两段各由谁决定（file:line）

**段标签那一半：模板控制。** `financial_report_engine.py:1727-1728`（`MultiSegmentFormatter.get_columns`）：

```python
if segment.label and col["fieldname"] in [p["key"] for p in self.period_list]:
    new_col["label"] = f"{segment.label} - {col['label']}"
```

`segment.label` 的来源链：`:1570` `segment_label = getattr(row_data.row, "display_name", "") or ""` → `:1565` ／ `:1579` 装进 `SegmentData(label=segment_label)`。实测 `column_breaks_readback_*` 键确认库里子行 `display_name` 就是我填的中文，与列头逐字吻合。

**中文是原样透传，没有翻译层。** 实测键 `segment_label_is_translated.uses_underscore_call_on_segment_label = false` —— `:1727-1728` 没有把 `segment.label` 套 `_()`。所以 `display_name` 写什么，列头就是什么，不经 translation 表。

项目列的 label 也来自同一个值：`:1724` `new_col["label"] = segment.label or f"Account (Segment {segment.index + 1})"`。**这意味着段标签被复用两次** —— 项目列头和期间列头前缀是同一个字串，无法分开设。

**期间那一半：引擎算出，模板层无入口。** `financial_statements.py:149-158`：

```python
def get_label(periodicity, from_date, to_date):
    if periodicity == "Yearly":
        if formatdate(from_date, "YYYY") == formatdate(to_date, "YYYY"):
            label = formatdate(from_date, "YYYY")
        ...
```

纯由 `periodicity` ＋ 日期算出，不读模板。且模板层根本没有承载它的字段（实测 `period_label_entry_points_in_template_layer`）：

- `Financial Report Row` 21 个字段：匹配 `label`／`header` 的 **0 个**，匹配 `period` 的 **0 个**
- `Financial Report Template` 7 个字段（`template_name`／`report_type`／`module`／`disabled`／`rows`＋两个 break）：匹配 `label`／`header` 的 **0 个**

与 V-25 的字段清点一致，本次独立复现。

## 三、离逐字「年初余额／期末余额」差多少

**差一条 ` - 2025` 尾巴，且这条尾巴关不掉（关掉就连中文一起没了）。**

能做到的最好形态：

```
年初余额 | 年初余额 - 2025 | 年初余额 - 2026 | 期末余额 | 期末余额 - 2025 | 期末余额 - 2026
```

想要的形态：

```
项目 | 年初余额 | 期末余额
```

**精确地说，以下三件在模板层控制不了**：

1. **` - {期间}` 后缀本身**。`:1727` 的 `if segment.label` 是唯一开关，且它同时管中文的有无，二者绑死。
2. **期间那一半的文字**。`YYYY`／`MMM YY` 由 `get_label` 硬编码，模板无字段可注入。要「年初／期末」这类中文期间名，此路不通。
3. **段标签被复用到项目列头**。`:1724` 与 `:1727` 读同一个 `segment.label`，所以项目列头必然等于分栏名 —— 上表里项目列头是 `年初余额`，而它装的是科目名（`资产合计`／`负债合计`），**语义是错的**。想让项目列叫「项目」、期间列叫「年初余额」，做不到。

另补一条：法定资产负债表是**一个项目列 ＋ 两个余额列**；这里的两段结构给的是**两个项目列 ＋ 每段两个期间列**，表格骨架本身也不是那个形状（V-26 `column_layout_cost` 已记过这一点）。

## 五、复核建议

1. **最该先看的：本条是 `go`，但「`go`」的含义要读准。** 命题问的是「列头是不是 `中文 - 2025` 形态」，答案是「是」—— 这同时意味着**中文能进去**（比 V-25 记的「列头是年份」乐观）和**尾巴去不掉**（对逐字合规仍是缺口）。若 B 步只摘「`go`」不摘形态，容易被读成任一极端。查法：读 `V29-out/cn-column-headers.json` 的 `OBSERVED_LABELS_A_statutory_literal` 与 `LABELS_CHAR_DUMP_A_statutory_literal`，后者给了逐字码位。
2. **观察范围（未验的）**：
   - 只跑了 `periodicity=Yearly`、`filter_based_on=Fiscal Year`、`selected_view=Report`、两个会计年度。**未验** `Monthly`／`Quarterly`／`Half-Yearly`、`Date Range` 模式、`selected_view=Growth` 或 `Margin`，以及三段以上。
   - 只验了 `report_type="Balance Sheet"`。**未验** `Custom Financial Statement` 这个 `report_type` 走不走同一个 `MultiSegmentFormatter` 分支 —— 若走另一条 formatter，结论可能不同。`:1386-1389` 的分支只看 `is_single_segment`，看上去与 `report_type` 无关，但**我没实跑另一种 `report_type`**。
   - **未验前端**。这里读的是 `execute()` 返回的 `columns` 结构。Desk 的 datatable 或导出 XLSX／PDF 时会不会再改 label（截断、再翻译、加换行），**没看**。若下游还要拿导出件给人看，这一段值得补。
   - **未验 `Section Break`**。`:1528` 有一条 `section_label` 路径（横向分节），我没碰。它是否给列头再加一层前缀，不知道。
3. **拿不准／我自己做的选择**：
   - **我加了第三个模板（`display_name` 留空）**，任务书没要求。理由：要说清「什么控制不了」，就得知道后缀是不是可选。结果确实有信息量（后缀可关但中文一起没），但这是我扩的范围，若不认可可只取 A／B 两组。
   - **两段都用 `Closing Balance`**，为的是两栏都能有活数字撑着列头；这不是法定资产负债表的正确取数方式（`年初余额` 该取期初），但本探针问的是**列头文字**，取数正确性不在射程内。
   - **2025 列全 0** 是站点账实（GL 只在 2026-09），非引擎故障。但因此「2025 列的 label 挂在一个全 0 列上」—— 我用 2026 有实值证明了列是活的，2025 列则只有 label 证据。严格说，**2025 那两个 label 我只见其名、未见其数**。
   - V-25 那条「探针自造的前导横线 `-2025`」这次**没有复现**：本探针不碰 `ignore_fiscal_year`／`accumulated_values`，走的是真报表路径，`hyphen_neighbourhood` 显示每个连字符两侧都有字符，无一列以 `-` 开头（`starts_with_hyphen` 全 `false`）。
